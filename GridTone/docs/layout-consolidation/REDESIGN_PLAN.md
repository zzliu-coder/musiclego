# 乐构：模块化工作界面重设计计划

日期：2026-09-19。状态：提案，未实施。

## 1. 结论与范围

采用“一个工作底座、按任务分组的操作托盘、尽量完整的音乐工作面”。保留暖白、珊瑚主动作和音乐磁贴浅厚度，重新设计信息架构、模块边界、布局和响应式规则。

这轮计划来自当前源码、用户提供的最新截图和独立源码遗漏检查。它是源码驱动的重设计方案，未重新逐页执行浏览器验收。历史 43 页仅作为对照索引，历史 PASS 不作为当前设计质量证明。

主工程仍为 GridTone，分支 codex/legou-tactile-2-2-1；复用当前工作区及未提交成果。当前是原生 JavaScript、HTML 字符串渲染与共享组件，无需引入新前端框架或复制工程。音乐模型、音源目录、schema、存储键和实际时间几何继续保留。

## 3. 总体空间规则

### 3.1 操作按作用域组织

1. 作品级：作品菜单、播放、速度、全曲律动、参考调性、保存与导出。
2. 工作区级：编排结构、混音组织、画布显示。
3. 目标级：当前音轨、音乐块、音符或时间段及其操作。
4. 草稿级：生成、试听、比较、采用；目标固定，不随随手选中另一块而改变。

作品信息只在全局入口完整出现；目标信息只在所属工作模块固定出现。危险操作必须紧邻作用对象与影响说明。

### 3.2 表面分工

- 工作底座：暖白表面，轻投影，一层容纳整个工作区。
- 操作托盘：浅暖灰底、短内高光或极轻凹感、8–10px圆角。只包住有共同任务的控件。
- 控件：普通命令安静；互斥选项仅突出选中项；播放、停止、音乐块保留可触感。
- 字段：延续透明底和底线，不增加按钮式凸起或凹槽。标签和单位随字段组成整体。
- 音乐画板：平静、连续，保留定位所需网格。装饰表面不能进入时间几何。
- 错误/过期：就地文字与明确状态，不能只依靠颜色或短暂 toast。

一层底座内允许一层任务托盘，托盘内部优先用间距和小标题分组。避免每个参数再套小卡片。层级主要靠语义、对齐、间距和少量表面差异建立。

### 3.3 密度与换行

- 操作模块是最小排布单元；标签、单位、目标名与核心动作不能被拆到无关行。
- 组内4–6px、模块内8–12px、模块间12–16px，统一引用组件参数。
- 常用文字标签保留，主要字号按已有组件规格；不继续缩字解决拥挤。
- 桌面常用按钮用现有32px紧凑规格；触控密度切为44px点击区。
- 不追求所有东西挤在一行。中等宽度使用明确设计的两行，禁止自动长出第三行操作岛。
- 宽度以工作区实际可用宽度为准，侧栏开启也触发布局切换；断点按最长真实内容测定。
- 非音乐内容禁止靠水平滚动找普通操作。时间轴、琴卷帘、混音通道列允许其必要的滚动。

建议初始分档：工作区可用宽度≥1180px为并排；760–1179px为明确两行；<760px为主任务与详情切换。此为设计起点，实施时用真实内容确认，不当作已实测值。

## 4. 新增或重整的共享模块

| 模块 | 职责 | 使用处 |
|---|---|---|
| WorkbenchFrame | 全局顶底栏、工作面、唯一工具槽的空间分配 | 编排、单轨、混音 |

| PanelFrame | 显式 header/context/body/status/actions 插槽 | 属性、演奏、生成、批量 |
| AuditionCommitBar | 试听范围、原稿/方案、停止、唯一主要提交 | 模板、候选、和弦、精细编辑 |
| BrowserFrame | 分类、结果工具、结果列表、详情 | 音乐库、音色库、和弦进行 |
| ResourceRow / EditableRow | 可对照的资源或重复字段 | 作品、鼓组、和弦事件、批量目标 |
| TaskDialog / ConfirmDialog | 简短任务与高风险确认的独立尺寸和动作规则 | 导出、移调、时间、删除、录音 |

复用已有 Button、Field、SegmentedControl、TrackHeader、MusicBlock、InlineNotice。新模块只负责表达与布局，继续调用原 editCommand、CandidateSession、PlacementPlan、播放控制器。

PanelFrame 改成调用者明确传入内容与动作，逐步撤掉“从任意 HTML 内找类名并搬到页脚”的隐式逻辑。Dialog 的动作也显式声明。迁移时保留原 data-action/data-field，逐页替换、逐页测试。

焦点层只负责进入、圈定、恢复；时间页签、移调字段显隐归各页面控制器。工作台菜单通过显式类型与锚点定位，停止根据中文标题字符串识别菜单。编辑目标、固定工具目标、试听对象各自传入，不能用隐式当前轨替代固定目标。

保存保留项会写作品，放在保留模块里明确说明；修改生成参数只产生草稿。用同一层级显示二者会误导，因此必须在视觉和文案上区分。

| 36 | 移调与适配 | 方式选择＋当前方式有效字段＋前后试听/确认 | 鼓轨不走音高变换；调式适配与仅改变参考调性不同 |
| 43 | 重命名 | 紧凑对象身份、单输入、取消/保存 | 三类名称（作品/轨/块）作用对象明确；长中文、IME、回车、取消分别检查 |

全局顶栏：作品入口、播放/停止/BPM、编排/混音、撤销/重做、模板入口。底部为播放循环、真实位置/当前试听范围、保存状态。两条都有明确模块分隔，品牌不单独占行。全曲 Swing 和参考调性从全局参数入口修改；局部面板可给短链接并标“全曲”。

## 8. 验收标准

### 8.1 视觉与空间

以下为待实现的验收目标，非当前实测结果：

- 1440×900下，全局顶底栏合计约100px以内；普通编排命令区域目标≤96px（不含异常横幅）；放大单轨主音乐画布目标≥600px。
- 1280×800下明确两行模块也要保持主要画板可用；工具槽开启后以实际剩余宽度验收。
- 模板库1440×900下结果滚动区目标≥视口高度60%，优先展示多行真实材料；非空详情试听与主采用无需先滚到底。
- 1100×700、691×682及短高620px状态分别检查；真正200%缩放另记，不能用一张等效小视口代替。
- 无横向溢出的普通操作区；无标签逐字竖排；无断开的模块背景；无孤立第三行按钮；相关对象和动作始终在一起。
- 菜单与字段可用底线、明确焦点和文字识别；关键作用范围不被省略号截断；禁用仍可辨认。
- 长中文名称、80字作品名、16项批量、64轨、长和弦事件列表、两种皮肤均加入状态矩阵；部分画布/列表允许滚动，不要求把全部数据挤入首屏。

### 8.2 交互与音乐正确性

- 每页打开、切换、返回、Esc、焦点、滚动恢复；正常、空、错误、忙碌、过期状态分别记录。
- 编排/音符复制剪切粘贴、关联/独立、时间选区、长音、删除时间、撤销重做。
- 模板点击与原生拖动、取消、跨边界替换、批量冻结及相关/无关编辑。
- 试听不写稿；应用一次撤销；候选目标固定；停止后声音资源释放。
- 旧作品比较音符、时长、力度、和声、资源ID、音色及编译音乐事件，不能只比较JSON合法性。
- WAV/MIDI/工程实际导出；忙碌、失败和当前试听导出分别验证。
- 当前核心测试需在最终构建上重跑；完整工程套件和600秒持续运行另有记录。未完成浏览器/真实设备/权限验证的项目明确 NOT_PROVEN。

### 8.3 防遗漏机制

建立机器可读的界面登记：ID、入口action、renderer、任务、模块、作用域、状态、回退、宽度模式、主动作、测试用例和证据路径。由源码action/renderer清单与登记表双向比对，新增未登记入口即提示。

静态扫描、DOM几何测量、截图审查、真实交互四者各自记录。静态扫描干净不意味着模块组织合理；单测通过不替代视觉；一页复用组件不代表所有变体已检查。验收包含用户本次截图的同类状态作为固定反例。
