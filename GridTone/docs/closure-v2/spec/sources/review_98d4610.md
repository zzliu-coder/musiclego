## 01 总体结论

建议保留“编排 / 乐句”两个专注布局，增加“混音”一级入口。编排和乐句共用同一套时间轴、音符编辑与音乐状态，布局只决定哪一块是主工作区。模板采用可收起的常驻素材架，支持预听、拖放与点击应用；创作工具根据目标显示相应操作，避免把所有功能放入同一张通用表单。

最新提交已经建立和声数据、规则旋律、鼓 / 贝斯 / 伴奏生成、八套配方、编排发展及多作品保存。下一轮重点是统一这些能力的操作合同、预听合同与界面呈现，并修复本轮复现的问题。现有音源、普通音符、工程 v3 和存储架构可以保留。

产品保持“模板快速套用 + 自由编辑 + 本地规则生成”。不增加教学模式、教程步骤解锁或固定创作顺序。具体操作缺少必要输入时，在操作位置说明并提供补齐入口。

## 04 两种布局怎样保留，才有实际价值

### 推荐布局

| 一级入口 | 主区 | 辅区 | 保持不变 |
|---|---|---|---|
| 编排 | 全曲时间轴 | 当前片段音符编辑，可收起 / 放大 | 选中的音乐对象、播放时钟、撤销和作品 |
| 乐句 | 当前片段音符画板 | 紧凑编排，可收起 / 放大 | 相同的轨道顺序、片段位置、选择与基础操作 |
| 混音 | 音轨通道、主输出与效果 | 可选的简短范围信息 | 当前作品与播放；不隐式切换到另一试听内容 |

选择理由：写局部时看得到其歌曲位置，组织全曲时能顺手修改当前片段。双焦点是对工作重点的调整，不需要再建两份工程或两套播放器。

默认比例可以从主区约三分之二、辅区约三分之一开始验证，用户可以拖动分隔线。比例只属于布局偏好。辅区允许收起；切换后保留用户现场。

### 相同组件允许有密度变体，但操作合同一致

当前源码的默认编排行高36px、片段高29px；编排主视图通过 `[data-workspace=arrange]` 改为74px和64px，并重新显示 M / S / 音量。差异来源可确认，但这组尺寸仍需最终 CSS 叠加后的完整页面测量。

建议显式定义 `ArrangementPane` 的标准 / 紧凑密度。改变行高和文字详略时，以下规则应一致：选择、拖动、复制、共享标志、循环范围、播放指针、键盘焦点及目标合法性。紧凑版减少常驻次要信息，不能悄悄成为一套不同的编辑器。只读缩略图若另有需要，应命名为“全曲概览”，不要让用户误以为它具备全部编辑操作。

`TrackHeader` 的选中、静音、独奏、音量数据也应共享。乐句左边额外的完整声音轨道栏与下方编排轨道头会再次占用重复空间，可改为紧凑轨道选择与当前轨信息，把常驻侧栏优先让给模板素材。

### 滚动状态需要按组件归属

当前 `app.js` 将滚动键拼为视图、轨道、片段、编辑子页的组合。编排横向位置因此与当前编辑对象绑定。推荐时间轴滚动归属作品的编排组件，片段音域与局部滚动归属片段编辑组件。两个布局的编排缩放可共享；需要独立时提供明确的联动偏好，不能靠偶然 DOM 重建决定结果。

## 05 混音的位置：完整工作区与候选操作分开

当前 `renderShell()` 已经有 `mix-workspace` 分支；定向渲染确认该分支没有包在 modal 内。实际顶部只有两个导航按钮，导致混音位置不明显。

建议顶部固定“编排 / 乐句 / 混音”。混音页可以边播放边调音量、声像、效果；切换布局只改变可见面板。进入时显示当前试听范围，提供直接恢复全曲的动作，不暗中改变之前试听内容。

“建议混音”属于一次候选计算：根据角色准备一组音量 / 声像设置，试听、应用或取消。这项操作可以使用临时面板；完整混音台属于工作区，建议混音属于一次性操作，入口可以直接放在混音台。

一般模态对话框会阻止与背后页面交互，所以适合需要专注确认的短任务；需要看着画板持续尝试模板与调音时，停靠面板更合适。参考 WAI-ARIA 的 modal 行为定义。

## 06 模板应成为手边的材料

### 当前应用路径

`CatalogUI.listing()` 打开“模板与素材”；TemplateCard 点击进入 detail；detail 提供新增 / 替换 / 新轨、目标轨道与片段、小节位置、移调方式、是否换音色等选项，再确认应用。

同类型模板默认新增到本轨首个空位，未默认落在用户当前编辑的句子。因此，即使已知道用户正在编辑哪段内容，仍然要求他重复选择目标和方式。

### 推荐的素材架

在乐句与编排共用一个可收起的素材架，分类为整套、和弦、鼓点、旋律、贝斯。提供搜索、最近使用和收藏即可，导入、资源详情放到完整素材库中。分类与数据仍来源同一目录。

素材卡片直接显示名称、小节数、适合用途和小型音符预览；试听按钮与应用动作分开。先点击比较，随后拖到目的地，或点击“应用到当前范围”。当前目标、时间范围、已有声音和和声参考能自动确定的内容无需重复询问。

### 落点合同

| 拖放 / 点击目标 | 默认动作 | 必须说明的影响 |
|---|---|---|
| 编排空白区域 | 在落点创建独立片段 | 轨道、小节范围、是否自动增加全曲长度 |
| 空白乐句画板 | 在明确的光标 / 选区写入普通音符 | 时长、原调或已选适配方式 |
| 已有音符区域 | 显示候选叠影，明确选择替换所选范围或创建变化副本 | 不覆盖未选内容；不把共享修改伪装成本实例修改 |
| 整套配方 | 显示多轨落点轮廓，创建配套轨道 | 新增几轨、持续多久；改变全局速度需显式选择 |
| 音色 / 鼓组 | 应用到目标轨道 | 影响该轨全部片段；鼓件角色对应关系清楚 |
| 超出片段长度 | 明确扩展或新增片段 | 不能静默截断；共享实例和邻接占用必须检查 |

点击与拖放调用同一个 `PlacementPlan`，同时用于预听、边界检查和提交。可用位置显示轮廓；错误位置解释原因；Esc取消零写入；一次放下对应一次撤销。

拖放需要保留无需拖动的单指针替代操作，例如选素材、点目标、应用。键盘操作也继续支持。这样保留乐器感，同时避免拖拽成为唯一入口。

### 应用前后的工作台位置

将模板拖入编排后保持编排布局与当前落点；填入乐句后保持乐句布局。不要因为统一的 `commit()` 习惯性进入 `edit` 而打断当前工作。当前 `catalogContext.commit()` 对非整曲结果调用 `openPatternInSession(... edit: true)`，未来需要把“提交音乐”与“提交后导航”拆开。

## 07 已有规则生成，怎样变成清楚的创作工具

当前 CreationUI 的同一个操作下拉列出12项：生成一句、保留节奏换音高、保留关键音改连接、只改结尾、回答句、鼓型变化、生成贝斯、生成伴奏、配套模板、发展编排、建议混音、鼓 / 贝斯 / 伴奏一起变化。鼓轨里也显示全部操作。

这把片段、轨道组、全曲和混音四种作用范围挤在一起。模板、布局和算法输入的先后关系没有通过界面清楚表达。

### 按任务与对象安排入口

| 所在对象 | 常驻或就近动作 | 可以展开的参数 |
|---|---|---|
| 编排区 | 套用整套、复制 / 重复、发展编排 | 段落长度、进入退出策略 |
| 和弦轨 / 和弦素材 | 选择进行、排列、弹奏方式 | 原位 / 就近 / 开放、音区 |
| 旋律片段 | 写一句、回答、改结尾、保留节奏换音高 | 音域、密度、色彩、变化种子 |
| 鼓片段 | 套鼓点、变鼓型、只改选定鼓件 | 最后一拍、疏密、力度倾向 |
| 贝斯片段 | 按和弦生成，跟随 / 呼应底鼓 | 参考鼓轨、实际支持的音域与节奏参数 |
| 伴奏片段 | 承托、呼应、加强 | 参考旋律、疏密和音区 |
| 混音台 | 音量、声像、效果、建议混音 | 角色与受影响轨道 |
| 应用设置 | 外观、动效、存储与资源管理 | 不放生成旋律、和弦进行等核心创作动作 |

一条上下文说明足够显示：作用于哪个片段、全曲哪个范围、使用哪条和弦轨、保留哪些内容。音域可用 C4–C6 表示，MIDI 数字作为高级信息；“再来一版”内部改变种子，默认无需让用户管理随机数字。

### 依赖只约束需要它的操作

按和弦写旋律需要覆盖该实例的和声；缺失时直接提供“从模板选择和弦 / 指定参考”。鼓点模板应用不要求先有和弦。全曲混音不要求选定一个音乐片段。当前生成仅支持4/8小节时，在生成前给出可操作提示，而不是填完全部参数才报错。

后台保存单向依赖：和声与鼓点 → 贝斯；和声与主旋律 → 伴奏。用户仍可自由跳到任何工具；来源变化后提示复核，不自动重写手工编辑过的内容。

## 08 本轮已核验的代码问题

### F01｜P1｜部分可见参数未进入实际算法

**位置：** `src/views/creation.js:19–23`；`src/music/ensemble.js:25–41`。

贝斯与伴奏模式显示发声音域、节奏密度与种子。算法却使用固定的基准音区：贝斯为36加根音音级，伴奏为60加和弦音级；它们没有读取 low/high，节奏密度主要只在鼓分支使用。

**定向实测 P01–P03：** 贝斯要求72–84，结果为36–45；贝斯切换稀疏 / 密集并改种子1→999，音乐字段保持相同；伴奏请求36–48与84–96，结果仍为60–71，音乐字段相同。测试对比忽略仅用于标识的ID。

**影响：** 用户调了参数却听不到对应变化，甚至超出明确请求的音域。

**处理：** 操作描述声明实际支持的参数。需要这项能力就实现；目前不支持就不展示。可确定性生成的模式不必承诺“换种子必变”，应准确说明其行为。

**验收：** 每个可见参数有对应行为测试；有效音域始终满足，无法满足时说明原因；密度变化在允许场景改变起音数量或明确目标统计。

### F02｜P1｜参数变更后候选已经失效，界面仍显示可应用

**位置：** `src/views/creation.js:44, 53–57`。

`handleField()` 清空 candidates，但大部分字段没有重绘，只有 mode 变化才 render。因此，旧候选栏仍在画面上。

**定向实测 P04 + Chromium：** 生成3版后，将种子改为123；内存候选为0，画面仍保留候选栏和“应用这一版”。点击后报“请先生成候选。”，没有提交。

**影响：** 尚未出现错误写入，但界面承诺与实际状态不一致。

**处理：** 参数变化同时更新候选状态、试听状态、绘图和按钮。采用 idle / generating / ready / stale / failed 的明确状态，失效后立即禁用应用并说明需要重新生成。

**验收：** 改任一输入立即反映失效；无候选时不能显示有效应用动作；重新生成后预听与提交使用同一份候选。

### F03｜P1｜发展编排的预听范围仍指向原片段

**位置：** `src/views/creation.js:28,53–55`；生产编排函数见 `src/music/recipes.js:arrangeSections`。

编排候选沿用原 trackId/patternId/clipId，未携带新插入范围。预听在没有 range 时回退到原实例位置和长度。

**定向实测 P05：** 原素材第1–4小节，准备在第5–12小节插入八小节编排；传给播放器的范围仍为 `[0,15360]`，期望新增范围为 `[15360,46080]`。

**证据边界：** 执行当前候选构造与预听代码，编排生产函数为明确的测试替身；未渲染或聆听音频。生产 `arrangeSections` 的读取结果与上述插入位置合同一致。

**处理：** 所有候选返回权威的输出范围和受影响轨道。新编排的返回值携带新的实例ID与范围；预听不自行从旧编辑对象推导。

**验收：** 原范围和新增范围放不同标识音，核验计划事件与实际导出音频，只播放所选新范围；应用后导航到相同目标。

### F04｜P1｜多轨一起生成按轨道排列运行，依赖结果不稳定

**位置：** `src/views/creation.js:33`；`src/music/ensemble.js`；`src/music/harmony.js:sourceHash/dependencyStatus`。

组合生成循环遍历 `base.tracks.filter(...)`。若贝斯排在鼓之前，它参考旧底鼓；随后鼓被重写，贝斯刚生成的来源记录立即过期。

**实测 P07/P08，另用真实 harmony 模块复核：** 将变化鼓件设为kick。轨道顺序“和弦、贝斯、鼓、旋律”时，贝斯只依据旧底鼓起音0和7680；鼓生成32个新底鼓起音，真实 `dependencyStatus` 返回stale。将相同内容排列为“和弦、鼓、贝斯、旋律”，依赖返回current，贝斯起音与新的鼓内容对应。

**处理：** 按明确的音乐依赖顺序生成，在同一个候选工程中先完成鼓、再完成引用鼓的贝斯、再完成伴奏。用户的轨道排序只影响视觉与组织。

**验收：** 保持音乐输入与种子相同，仅重排轨道顺序，不应改变相同任务的音乐结果；生成完成时所有新依赖指纹有效。

### F05｜P2｜跨入参考范围的持续音被忽略

**位置：** `src/music/ensemble.js:6`。

`sourceNotes()` 只保留换算后起点大于等于0的音符。开始于范围之前、但持续进入范围的音被丢弃。

**实测 P10：** 一条音从0持续到7680 ticks，查询3840–7680，返回0个音。

**影响：** 伴奏避让逻辑可能把正在持续的主旋律当作空白。

**处理与验收：** 按区间交集读取并裁剪可见段，保留起音与持续的不同语义。对跨边界、恰好结束于边界、恰好起于边界分别测试；底鼓的“起音参考”和旋律的“占用参考”不要混用。

### F06｜P2｜全曲类操作不必要地依赖已放置片段

**位置：** `src/views/creation.js:6–10`。

`open()` 对所有模式先要求选中编排中的片段；但整套配方新增轨道、建议混音和部分编排操作的自然目标是作品或范围。

**实测 P06：** 移除当前轨的编排实例后，无法打开该通用入口，即使希望使用独立新增轨道的配方。

**处理与验收：** 按命令范围准备目标。配套模板可从空作品的编排位置开始；混音直接以作品为目标。旋律生成保留对确切实例的要求。

## 09 状态与组件的下一轮整理

### 不需要为两个布局复制音乐状态

| 层 | 内容 | 改变时的影响 |
|---|---|---|
| 作品文档 | 实际音符、片段、实例、和声、生成来源、用户保留项、音色、混音 | 确认后进入音乐撤销、保存与播放更新 |
| 共享选择 | 当前轨道、片段、实例、音符ID与操作焦点 | 改变编辑目标；不改音乐，不自动覆盖候选目标 |
| 布局偏好 | 编排/乐句/混音、停靠面板、密度、高度、组件视口 | 只改变显示与本机偏好 |
| 素材现场 | 分类、筛选、收藏、浏览位置、预听 | 不进入音乐文档 |
| 放置 / 生成现场 | 固定的目标、原稿版本、范围、参数、候选、拖放轮廓 | 应用前只作预览；过期或取消时不写原稿 |
| 播放现场 | 播放时钟、范围、循环、临时只听、候选返回状态 | 所有布局共用一个管理者 |

常驻素材架与非模态生成面板允许用户继续操作画板。因此，目标切换规则需要在这轮明确：候选生成时锁定其track/clip/range；用户切到另一片段，旧候选不能自动改写新目标。原稿发生相关修改时提示过期；简单滚动画板不应让候选无效。

### 一个轻量操作描述，避免参数与实现脱节

为操作记录 `scope`、允许目标类型、必要输入、实际参数、候选输出、预听范围和应用方式。例：

```text
生成贝斯
作用对象：当前贝斯片段实例
必要输入：覆盖目标范围的和声
可选输入：底鼓参考
支持参数：跟随/呼应、已经实现的音域与疏密
输出：普通音符 + 来源 + 实际范围
预听：同一候选的单轨或伴奏合听
应用：一次事务，必要时建立独立变化
```

组件据此只显示相关参数，命令根据相同描述检查输入。这个表可以是一份普通 JavaScript 配置，无需引入庞大的插件框架。

### 组件关系建议

```text
WorkbenchShell
  ├ TransportBar
  ├ WorkspaceTabs（编排 / 乐句 / 混音）
  ├ TemplateShelf（同一素材选择器）
  ├ ArrangementPane（标准 / 紧凑）
  ├ PhraseEditor（普通 / 放大）
  ├ MixerPane
  └ CreationPanel（按目标显示操作）

Template / Recipe / Generator
  → PlacementPlan / Candidate
  → PreviewPlan
  → Command commit
  → Document + History + Save + Audio
```

设计系统继续共用tokens、组件变体、交互状态和焦点规则。当前14个样式文件还包含历史material/studio与最终legou覆盖，不必一次全部改写；先把同一组件的尺寸和状态归回组件文件，布局文件只管顺序、分区与显式密度。

## 10 建议施工顺序与验收

| 顺序 | 重点 | 必须通过的验证 |
|---|---|---|
| A：操作与预听合同 | 修正参数无效、候选失效、编排预听、依赖顺序和持续音范围 | 每个可见参数有实际行为；预听范围等于候选范围；依赖不受轨道顺序影响 |
| B：三个工作区与组件归位 | 现有混音升一级；编排/乐句显式密度；滚动与焦点按组件归属 | 相同基础操作在两布局结果相同；切换不改音乐、试听对象与撤销；返回现场准确 |
| C：常驻模板架与放置 | 同一目录、预听/点击/拖放、目标轮廓、长度与覆盖处理 | 空白和已有内容均有清楚行为；错误/取消零写入；共享提示；一次撤销；不强行跳页 |
| D：上下文创作与全流程 | 按角色显示规则工具；全局任务独立目标；参数高级展开 | 从空作品也能套整套；缺输入就近补齐；生成保留用户内容；保存重开和导出一致 |

每批保存固定提交、输入作品、动作、输出作品、日志；有预听逻辑时保存编译事件与实际渲染。避免只统计按钮是否存在。

长期成功路径：

**编排中拖入和弦模板 → 原位添加鼓型 → 打开旋律片段 → 在旁边选择节奏骨架 → 按该范围和弦生成 → 保留几个音 → 只改结尾 → 返回编排排出A′ → 打开混音 → 全曲试听 → 保存重开。**

补充交叉用例：切换布局时仍在预听；拖动中换目标或取消；候选未应用时改和弦；改变轨道排序；跨范围持续音；4/8生成与1/2/16片段兼容提示；长模板碰到邻接片段；同一片段跨多个和声上下文。

## 13 最终判断

乐构已经从基础编辑器发展出可用的规则生成底座。下一步应把“看什么、改什么、依据什么、应用到哪里”四种关系明确分开，再让模板、候选和画板在同一工作台中直接交互。

最需要实现的体验是：**材料就在旁边，目标就在画板上，拖放或点按就能试；当前结果、保留范围与影响对象始终清楚。**
