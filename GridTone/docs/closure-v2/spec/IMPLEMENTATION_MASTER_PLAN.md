## 2. 全部范围如何界定

### 2.1 最终产品包含

三个一级工作区：编排、乐句、混音。编排和乐句共同使用一套音乐组件与状态，主辅区可调、可收起。常驻素材架、独立试听、拖放/点击/键盘放置。和弦进行、鼓型、旋律、贝斯、伴奏、整套配方、局部变化与8/16小节发展。按已有内容进行本地规则生成；保留音高/节奏/全部/时间范围及休止；就近解释。统一音色与模板分组、设计系统和生产组件。可靠多作品、迁移、恢复、导出，以及现有录音/自定义采样/可选真实音源入口的闭环。

### 2.2 已明确排除的范围保持不变

教学模式、课程步骤、教学进度和强制解锁均不加入。账号、云协作、大模型服务、VST宿主、大规模新合成器、通用插件市场、完整古典四部和声求解、自由连线画布等，没有进入原R0—R9承诺，本计划不把它们扩成额外项目。更早的远期愿景不等同于本轮已约定交付。

“全部”覆盖原正式计划与两次审查的既定工作及本轮交互变更；以这份固定范围防止边做边追加无限目标。实施中发现支撑本范围所必需的新缺陷，进入同一总账并在本轮修完。

### 2.3 曾延期的事情仍有明确去向

小屏/触屏曾在1.6合同中另议。本计划按你现在要求完整收尾，将它和真实来源持久化、实际录音/采样路径、浏览器兼容及音乐听评放入C10必需项。不能只把它们记在“以后优化”。这表示验证现有网页功能，不表示新增原生移动应用。

实际设备或监听条件不足时，记录BLOCKED并由实施负责人安排有条件的执行者完成。证据缺失期间只能称候选。计划不会让开发者用“自动化模拟了”冒充真机，或用“渲染了音频”冒充审听。

## 4. 必须先固定的共同合同

### 4.1 状态归属

| 层 | 唯一职责 | 持久化/撤销 |
|---|---|---|
| ProjectDocument | 音符、轨道、片段、实例、和声、资源、保留项、生成来源、混音 | 随工程保存；确认内容改动进入历史 |
| Selection | 当前track/pattern/clip、noteIDs、时间选区和操作焦点 | 两布局共享；不改音乐 |
| Workspace | 布局、显式密度、停靠/高度、编排视口、每片段视口 | 按作品/组件保存；不进音乐撤销 |
| CatalogSession | 搜索、分类、最近、收藏和当前素材 | 不进作品音乐；库信息按本机偏好保存 |
| CandidateSession | 固定目标、输入/参数指纹、输出、状态、比较槽、放置ghost | 应用前临时；不能整稿覆盖并行修改 |
| PlaybackContext | 时钟、范围、循环、Solo、预听及返回状态 | 一个管理者；全曲导出不继承临时Solo |
| DerivedAnalysis | 和声匹配、修改提示、依赖状态 | 可计算缓存；必须有输入依据 |

**全局选择、候选固定目标、鼠标悬停目标分别保存。** 光标经过B不意味着A候选目标变成B。当前轨道变化不会偷偷更换生成参考。

### 4.2 操作合同

每种动作由一份轻量描述驱动，至少定义：操作ID、作用范围（作品/轨组/实例/选区）、允许角色、必要来源、真实支持的参数、默认值、校验、输出、预听与提交方式。它是普通JS配置，服务当前编辑器，不做插件平台。

界面自动展示已有能力，但不以隐藏参数完成已经承诺的功能。例如贝斯/伴奏音域和密度在本计划中必须实现；没有随机性的纯混音配方可以不显示seed。参数必须有差分行为测试，不强求每次不同seed都不同。

### 4.3 候选与放置返回值

```text
Candidate / PlacementPlan
  candidateId, projectId, operationId
  target: trackId / clipId / selectedRange
  baseRevision + relevantInputFingerprint + parameterFingerprint
  output: 普通音符 / 新片段 / 实例排布 / 混音参数补丁
  affectedTrackIds, affectedClipIds, outputRange（绝对ticks）
  requiredAssets, sourceVersions, generatorVersion, seed
  conflictChecks, auditionModes, resultingSelection
```

局部音符保存相对ticks；候选声明自己的实际全曲范围。音符插入、共享断开、元数据和资源写入必须作为同一事务。历史用规范化音乐变化判断；相同音符仅换ID不算候选音乐差异。

### 4.4 两类流水线

创作依赖：和声/节奏→旋律/贝斯/伴奏→变化/编排。发声处理：实际音符→琶音/移调/律动→音源→效果→混音。只有前者缺输入时限制相应动作，其他手工与模板入口始终可用。

### 4.5 模块整理的最低要求

```text
src/
  app.js                   启动和连接；不再承接新音乐算法
  model.js / document/    约束、校验、迁移（可渐进拆分）
  commands/                内容提交、复制、放置与事务
  session.js               当前选择与工作区偏好
  creation/                操作描述、候选会话、放置计划
  music/                   和声、区间、旋律、节奏、声部、配方
  catalog.js / catalog/    数据目录、版本、角色、资源
  playback.js / audio/     播放、预听、音源、输出
  storage/                 文档、列表、恢复、revision与队列
  ui/                      生产组件、焦点、手势、DOM patch
  views/                   三工作区、素材架、按任务创作面板
  styles/                  语义参数、皮肤、组件、布局
```

目录可以合并小文件；按职责和依赖验收，不按文件数验收。通用DOM patch从音乐命令模块移出。原子提交、统一候选与播放不能在每个UI类里分别再实现一份。

## 8. C3｜和声、区间与跨轨依赖收口

2. 拖入或点放四小节和弦，看到落点与参考范围。
3. 原位加鼓点，按当前鼓组角色正确发声。
4. 建立/选择旋律片段，从素材架选节奏骨架。
5. 读取该实例真正覆盖的和声，生成最多三版。
6. 在同一伴奏下切换候选，听到候选自己的范围。
7. 保留节奏及几个音；只重写连接或结尾。
8. 在候选未应用时修改无关声部，应用后该修改仍在。
9. 创建独立A′，原A片段和其共享实例保持原关系。
10. 对鼓/贝斯/伴奏组合生成；重排轨道后相同输入结果一致。
11. 放入第5—12或第9—24小节形成新编排，预听新区域。
12. 在编排与乐句切换，选择、范围、视口和播放保持合同。
13. 打开第三入口混音，比较建议/原版，取消或应用。
14. 临时只听部分轨道，再恢复全曲。
15. 保存A，新建B并编辑，重开A仍完整。
16. 导出全曲/当前范围WAV、MIDI、工程，核对各自内容。
17. 关闭/刷新后重开；新运行实例读取工程和自定义资源。
18. 使用真正交付HTML再重复关键步骤，并从源码包独立构建核对。

两种布局各跑一条；素材的拖动和点击各跑一次；桌面完整路径、Android主路径、键盘关键路径分别保存证据。补充失败路径：缺和声、缺鼓件、超长度、共享冲突、保存冲突、候选过期、下载失败、取消后迟到。

## 19. 怎样认定一个批次与整个项目完成

### 19.1 每个保存点的最低证据

固定提交/构建hash、改动与影响模块、关闭的需求ID、输入工程、操作、输出工程、自动日志、真实页面截图、相关实际音频、回归结果、剩余项及下一批依赖。保存点可以标WIP，但只有验收通过才允许使用完成标签。

### 19.2 不再使用模糊的完成统计

状态使用NOT_RUN / PASS / FAIL / BLOCKED。本计划的required项不能临时改optional或N/A完成销账。若用户之后明确变更范围，需要单独的书面变更、受影响ID和调整后的总体说法；不得自行缩小再声称原范围全部完成。

历史83个PASS单独保存，不直接复制到最终表。新证据应有提交、构建hash、环境、输入、断言和输出文件。人工监听/设备记录附执行者和日期。审听标准是适合已声明用途且无未处理问题，不是宣称普遍审美优越。

### 19.3 最终门槛

| 条件 | 必须达到 |
|---|---|
| 需求覆盖 | 原87项全部有处理落点，新增缺陷与交互需求全部有对应验收 |
| 功能状态 | 范围内所有required完成；FAIL/BLOCKED/NOT_RUN/PARTIAL均为0 |
| 已知问题 | 已知范围内未关闭问题为0；反证必须有修复回归 |
| 状态与数据 | 原稿/候选/监听/布局隔离，保存与重开可靠，迁移和复制不损关系 |
| 视觉与操作 | 三工作区、素材架、生成与全部现有面板按同一组件合同运行 |
| 听感与设备 | 必需听评、真实存储、支持设备和资源路径均有实际记录 |
| 发行包 | 实际文件与已验收构建一致，干净源码复建一致，文档准确 |

零已知范围内问题不代表数学上保证以后不会发现任何未知缺陷。它表示：本计划当前已知承诺没有未完成项，所有验收与证据可复核。

### 19.4 不能接受的替代证明

“新增一个文件”不能代替职责边界；“已有按钮”不能代替功能；“参数进入设置对象”不能代替算法使用；“三版ID不同”不能代替音乐差异；“预听方法调用成功”不能代替范围正确；“非静音”不能代替好用与听感；“模拟器通过”不能代替真机；“README说通过”不能代替当前代码证据。
