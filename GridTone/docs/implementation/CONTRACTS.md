# 乐构 1.6 实施合同

## 本轮范围

模板优先、自由编辑、基于显式输入的规则生成。没有教学模式、步骤解锁、账户或在线模型调用。

2026-09-18 用户补充：**小屏体验留到后续专题**。本轮视觉与交互验收聚焦桌面 1280 / 1440；已有小屏兼容保留，触屏命中区域、移动端布局和真机手势不作为本轮完成门槛。

## 音乐文档 / 编辑现场 / 播放现场

| 层 | 保存内容 | 写入规则 |
|---|---|---|
| 文档 v3 | 普通音符、轨道角色、片段引用、音色快照、音源、和声说明、保留项、生成来源、混音 | 通过事务提交；成功一次撤销，失败和取消零次 |
| 编辑现场 | 当前轨道 / 片段 / 实例、选区、光标、网格、缩放、显示调性 | 不进入音乐历史；工作区偏好按作品隔离 |
| 播放现场 | 试听对象、位置、循环范围、临时 Solo、候选返回现场 | 由 PlaybackController 管理；导出全曲忽略临时 Solo |

`executeCommand` 对克隆的文档计算并校验，返回结果、受影响对象与错误。应用层 `mutate` 统一调用；实时指针手势在落定时进入同一个 `markChanged` 提交入口。表面动画不延迟提交、音频启动或停止。

## 时间与身份

- 一拍 960 ticks；4/4 一小节 3840 ticks。合法片段长度统一为 1 / 2 / 4 / 8 / 16。
- 小数 ticks 保留。时长减半最短为 1；加倍超出片段时拒绝。中点拆分保持总长；光标拆分只拆穿过光标的所选音符，每半至少 1 tick。
- 界面吸附仅属于输入手势，时间运算不暗中量化。
- 工程内轨道、片段、实例、音符 ID 全局唯一。复制整条轨道重建身份，保留副本内部共享拓扑；复制工程重映射保留项和生成引用。
- 生成默认只修改当前实例：共享片段会先创建独立版本。普通编辑仍遵循可见的共享关系。

## 作品保存

- IndexedDB 数据库沿用 `gridtone-local-v1`，结构版本升级为 2。新增 `documents`、`project-index`、`recoveries`、`metadata`；旧 `projects` 原始数据保留。
- 入队时抓取完整快照。每个保存事务同时校验 revision、写文档和更新列表；只有 `transaction.oncomplete` 后显示已保存。
- 作品切换串行执行。先保存当前作品，再确认目标持久化，最后替换编辑现场。失败时继续保留当前内容。
- 同一作品跨页面更新发生 revision 冲突时拒绝覆盖，可重试、下载、另存副本或明确放弃本页修改。
- 每作品最多 10 个恢复点、间隔至少 30 秒；活跃作品与恢复记录分别使用约 120 MB 的应用预算。浏览器实际配额仍可能更小。
- 同编号导入默认变成新作品；删除作品不删除其他作品的资源。撤销历史不跨作品。
- v1/v2 读取后迁移为 v3；用户下载的旧文件不改写。生成音符是播放与导出的事实来源，旧版本不具备 v3 创作关系编辑能力。

## 和声、生成和依赖

- 和声时间表挂在 pattern 上，使用片段内相对 ticks。查询时必须提供来源轨和目标实例，映射到歌曲位置，检测空档与重叠。
- 参考主音 / 音阶不改写显式和弦。来源轨演奏移调只计算一次；写目标音符时反算目标轨移调，避免双重移调。
- 音符、实例位置或演奏移调改变会让对应来源指纹变化；名称、音量和声像不影响音乐指纹。失效只提示，不自动连锁重写其他声部。
- 规则旋律生成支持 4 / 8 小节单声部。节奏和音高使用分开的确定性随机流，最多 12 次尝试，返回最多 3 个有音乐差异的候选。
- 保留音高 / 节奏 / 全部、范围及其中休止均为硬约束；无法满足时解释原因。解释标签来自当前和声，属于分析结果，不会自动锁住音符。
- 候选保存原稿指纹、参数、来源与最终音符。预听和应用使用同一份候选；原稿变化后拒绝过期应用。
- 鼓按显式鼓件角色映射。贝斯可参考底鼓，伴奏可参考旋律；组合生成按单向依赖计算后整批提交。
- 8 / 16 小节编排在指定空白位置插入；共享重复保留引用，回答 / 结尾变化使用独立片段。容量冲突整次拒绝。

## 容量和发行

结构上限：64 轨、256 小节、100,000 音符、自定义音源约 24 MB。结构上限不代表所有设备都能实时播放该负载。WAV 每次最多 3 分钟及 20,000 音符，MIDI 最多 15 个旋律通道；超限明确报错。

工程自动测试、音频渲染指标、实际听感、物理设备体验分别记录。人工听感未评审时标 `NOT_RUN`，发行状态为工程候选版。`verify:release` 对仍为必需且未通过的验收项返回非零值。
