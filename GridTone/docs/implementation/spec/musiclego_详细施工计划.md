# 乐构 musiclego：模板优先的详细施工计划

 **计划版本：1.0 · 状态：待实施 · 基线：乐构 1.5.0 / `0f99777`** 

本计划把产品定位固定为： **快速套用音乐模板、自由绘制与修改、按已有材料进行算法生成、组织编排、混音并保存灵感。** 

用户可以从任何材料开始。模板、和弦、鼓点、旋律、贝斯和编排都是可直接使用的工具。教学属于用户未来的使用场景，本轮产品不加入教学模式、课程页面、教学进度、双模式分流、强制步骤或按关卡解锁。

 **施工次序约束实施工作；功能依赖只约束具体操作需要的输入。** 例如“跟随和弦生成旋律”需要先指定和声来源。界面就近显示“选择参考和弦”，同时保持手动画音、其他模板和其他编辑功能可用。

本计划依据固定版本审查制定，所有新增能力、文件结构、验收数量及性能指标均为施工要求或测试目标，尚未实现或实测通过。此前审查报告中有关“跟着做四小节／创作指引”的建议，由本计划的产品边界取代。

## 1. 总体目标与交付边界

### 1.1 最终使用体验

打开编辑台，立即能画音或打开模板库；选一套配方，可一次铺入和弦、鼓点和贝斯；在目标片段点“生成旋律”，得到可试听的候选；保留喜欢的音高或节奏，再局部重写；创建 A′、摆放片段、调整混音；把作品单独保存，随时回来继续。全程不需要大模型、账号或远端生成服务。

模板入口与手工操作并列。产品不要求用户按固定创作顺序使用。候选解释只说明当前内容与操作范围，例如“这一音是句尾落点”“本次保留节奏，只变化音高”。

### 1.2 本轮保留与新增

| 类别 | 处理方式 |
|---|---|
| 现有声音引擎、WAV/MIDI 导出 | 保留，通过统一音乐事件计算和回归测试保障兼容；只修改与已确认问题有关的接口。 |
| 编排／乐句两个工作视图 | 保留。模板和生成入口前移，混音保持可达；不再引入第三套编辑器。 |
| 音符、片段、编排实例模型 | 保留，补充作用范围、统一修改事务、复制规则和可选创作元数据。 |
| 现有预设、模板和素材包 | 保留 ID 与旧作品资源引用；逐步补齐分类、依赖、参考和声和适用角色。 |
| 新增能力 | 多作品管理、统一设计系统、和声时间表、配套模板、局部算法生成、修改建议与自动生成保留项、段落变化。 |
| 本轮暂不扩展 | 教学模块、云同步／协作、账号系统、大模型接入、大量新合成器、VST 宿主、完整古典四部和声求解、自由连线模块画布。 |

### 1.3 决策顺序

 **作品正确且可恢复 → 统一操作与界面标准 → 模板能成套使用 → 生成知道上下文 → 局部变化可控 → 整体编排与最终验收。** 

不通过追加皮肤文件掩盖组件冲突，不以新增模板数量代替配套使用验证，不以音符合法性测试代替主观听感评审。

## 4. 开工前固定的架构规则

### 4.1 六类状态与两种流水线

| 数据 | 所属 | 保存／撤销规则 |
|---|---|---|
| 音符、片段、实例、音轨、音色、效果、静音、和声、已确认生成来源和保留项 | ProjectDocument | 保存到工程；内容修改一次提交、一次撤销。 |
| 当前工作视图、选中对象、工具、滚动、音域、面板尺寸、素材筛选 | EditorSession | 可保存本机偏好；浏览操作不污染音乐撤销。 |
| 当前播放目标、位置、循环、临时 Solo、预听返回现场和异步请求 ID | PlaybackContext | 不写入默认作品混音；默认全曲导出忽略临时 Solo。 |
| 候选版本、待应用参数、临时保留项、原稿快照和取消状态 | GenerationSession | 取消即丢弃；确认应用才进入工程。 |
| 音符角色、修改建议、依赖是否过期 | DerivedAnalysis | 从文档与规则计算；缓存必须有版本／输入依据。 |
| 预设、鼓组、模板、配方及其资源依赖 | Catalog | 目录全局管理；工程带已使用定义和必要资源快照。 |

创作流水线处理“和弦／节奏等输入如何形成新音乐”；发声流水线处理“已有音符如何发声”。`track.pipeline` 继续负责后者，不塞入教学阶段或生成流程状态。

### 4.2 唯一音乐修改入口

建议最小接口采用 `executeCommand(command, target, payload)`，成功时返回新文档及 `affectedIds`、`changeKinds`、可选选择变化；失败时返回错误，保持原稿。提交入口统一处理历史、依赖失效、保存和音频更新。

处理顺序： **捕获目标及文档版本 → 计算候选 → 校验受影响结构 → 提交一次 → 更新选择 → 标记依赖 → 排队保存 → 精确更新音频。** 

音量／声像采用参数更新；乐谱变动更新未来事件；音源和轨道拓扑变动才重建需要的音频资源。避免每个拖动帧全曲克隆与完整校验。拖动期间只计算预览，结束时形成事务；Esc、pointercancel、失焦取消时恢复原稿。

只在这一入口管理跨功能写入。控件和视图读取状态并发送命令。运行中的 audio node、Promise、DOM 节点不进入工程文档。

### 4.3 时间、长度与版本

时间继续使用 960 ticks／四分音符，4/4 小节为 3840 ticks；默认显示 16 格。基础片段允许长度统一为 `[1,2,4,8,16]`。轨道、歌曲、音源容量沿用现有上限，本轮不以扩大上限作为交付目标。

本轮允许原有有限小数 ticks，避免对旧工程做未经用户选择的全曲取整；最小音符时长保留 1 tick。数学运算不依赖当前吸附网格。新算法优先产生明确细分的整数时间，浮点比较使用统一误差范围。

 **建议新工程文档使用 version=3** ，为和声、生成来源和保留项建立受校验的字段；v1/v2 使用明确迁移。文档版本、数据库版本、模板版本、生成器版本分别管理。文件扩展名继续为 `.gridtone`。旧程序对 v3 的支持不作保证，也不静默导出为会丢失元数据的 v2。

R1 建立 v3 基础合同和迁移；R4/R6 实现可选字段的具体用途。迁移先解释旧数据，再按新合同校验；旧版已经导出的16小节v2工程应按新合同接纳，不能先被旧长度校验器拒绝。最终不能留下未校验的任意元数据。旧文件的音符、实际音色定义、播放参数和自定义资源保持原样；新 ID 只在明确复制为新对象时分配。

### 4.4 模块整理遵循职责

推荐结构如下。它是目标责任边界，允许把小而紧密相关的实现先放同一文件；不按目录数量验收。

```text
GridTone/
  src/
    model.js                  # 文档模型与纯音乐规则，逐步减小职责
    document/                 # 新增：约束、校验、迁移、类型说明
    commands/                 # 新增：音符、片段、音轨、模板应用事务
    session.js                # 编辑会话，保留
    playback.js               # 统一播放与预听，保留
    storage/                  # 从 io.js 拆出作品/恢复/保存队列
    music/
      progressions.js         # 现有进行生成，扩展来源输出
      harmony.js             # 和声元数据与时间范围解析
      context.js             # 实例位置、依赖、角色、保留范围
      generation/            # rhythm、melody、bass、variation、seed
      explain.js             # 有依据的角色与修改提示
    catalog.js               # 目录校验与资源解析
    ui/                      # 组件、焦点、手势、候选公共交互
    views/                   # 编排、乐句、混音、模板与作品
    styles/                  # tokens、themes、components、layout
    audio.js、audio/、io.js    # 发声与导出，保留有效实现
    app.js                   # 启动与协调；不新增业务算法
  catalog/                   # 预设、模板、配方的纯数据
  tests/                     # 当前版本唯一测试清单
  docs/implementation/       # 合同、分批记录、证据和组件规范
```

继续使用现有单文件构建和资源清单。新模块必须加入统一构建入口。通用 DOM patch 从音乐命令文件移到 `ui/`。本轮不引入 Redux、状态机框架、插件注册市场或全量前端重写。

## 6. R1｜统一工程规则、修改事务与播放范围

 **目的：保证界面允许的操作能够保存重开，修改结果与名称一致。前置：R0。** 

### 施工顺序

 **R1.1 先统一长度与时间。** 把允许片段长度移到唯一合同，完整覆盖 16 小节。片段变长时检查全部共享实例；空间不足则拒绝，提供“创建独立副本／增加歌曲长度后再试”的可执行选择。缩短默认拒绝截掉音符；显式裁剪作为独立操作，不能默默丢音。

时长减半采用 `max(1, duration / 2)`；1 tick 时保持原值并提示已到最短。2 倍时长越界默认拒绝整次操作，用户可以显式选裁剪。精确二等分要求两个部分均至少 1 tick；不足则禁用并说明。按游标拆分以游标为界，总时长守恒。量化使用独立命令和指定网格。

 **R1.2 再统一提交路径。** 先迁移画音、移动／拉长、删除、复制、片段长度和音色应用，再迁移滑杆与生成／模板提交。滑杆整次拖动只占一个历史项。命令失败恢复原稿与选择；任何无变化操作不产生历史。

 **R1.3 补齐完整复制。** 音符复制使用新 ID；独立片段复制重建内部音符 ID；共享引用复用片段 ID。整轨复制包含音色、声部角色、混音、片段和实例，通过一次 ID 映射保持新轨内部共享关系，同时与原轨隔离。引用资源保留相同内容身份，不重复下载或丢失资源。

 **R1.4 固定播放状态合同。** 播放目标持续可见；停止清理主播放、预听与待启动任务。候选试听记录返回现场。浏览不改变目标；切换作品结束旧播放；同一作品切换布局保留显式试听范围并始终显示范围。切换局部试听片段重新定位到新内容。默认全曲导出使用作品混音，忽略临时 Solo；“导出当前试听”独立选择。

 **R1.5 区分错误类别。** 格式错误、版本不支持、资源缺失、存储不可用、保存冲突、音频启动失败使用独立错误码和清楚文案。小屏优先露出播放／停止、保存状态、试听对象和撤销入口。

## 7. R2｜按作品保存灵感，解决异步覆盖

 **目的：A、B 两个作品可以反复切换，互不覆盖。前置：R1。** 

### 施工顺序

R2.1 从 `io.js` 拆出最小作品仓库，保留导出模块。作品按 ID 独立保存；另存最后打开的作品 ID。作品列表只需要名称、修改时间、轨数、小节数和可选短备注。提供新建、打开、改名、复制为新作品、下载和明确确认后的删除。普通新建直接进可发声空片段，模板入口始终可用。

R2.2 恢复点按作品管理。保留至少30秒间隔、每作品10个的初始政策，同时设置总存储预算与“空间不足”提示；资源仅按需要加载，列表不一次反序列化全部采样。删除／清理只处理指定作品，不能删除其他作品引用的资源。

R2.3 保存任务必须绑定 `projectId + contentSnapshot + revision`。任务排队时捕获快照，不能等异步执行时再读取当前全局 project。旧任务完成时只更新对应作品状态。切换作品前完成当前保存；失败时保留原作品，提供重试、下载或明确放弃后切换。

R2.4 使用事务同时写工程与列表元数据；“已保存”只在事务完成后显示。IndexedDB 的事务完成／终止机制用于这里的成功与失败判断，不能仅凭某个 put 请求已发出判断已保存。[S7]

R2.5 迁移旧 autosave 与恢复点。迁移保留原始备份，记录完成标记；重复启动不会生成重复作品。可识别旧恢复点按其 project.id 归属，无法识别的保留在迁移记录里，不静默丢弃。

R2.6 处理多个标签页对同一作品的写入冲突。用持久 revision 在同一读写事务中比较；检测到更新时提示载入新版本或保存为副本。不同标签页无需复杂协作协议，也不能静默后写覆盖。数据库升级被其他页面阻塞时显示原因与关闭旧页面的操作提示。[S7]

### 历史与文件的区别

撤销历史归属当前作品，切换作品不混入另一作品的历史。每个作品会话可保留独立历史；重启后依赖恢复点，不承诺持久化所有撤销步骤。打开外部工程且 ID 已存在时，默认导入为副本；覆盖必须由用户明确选择。

### 保存点条件

真实同源页面完成保存→刷新→恢复，A/B反复切换无覆盖；存储失败不会冒充成功；旧 autosave 迁移可重复验证。内联页面内存测试不能替代真实来源持久化验证。

## 8. R3｜统一设计系统、把模板放到手边

 **目的：后续功能直接使用同一套组件；常用操作容易找到。前置：R2。** 

### 施工顺序

 **R3.1 先做组件和样式清点。** 记录当前生产DOM、按钮角色、字体、断点、弹窗、画板、轨道头；建立旧类名→新语义的映射。保持主要信息结构和用户已熟悉的操作，不再来一次全站换设计风格。

 **R3.2 建唯一语义参数。** 基础值负责颜色／间距／圆角；语义值负责内容层、控制层、主文字、辅助文字、选中、危险、焦点；组件只引用这些语义值。皮肤只覆盖皮肤语义值。参考 Design Tokens 的命名与引用方式即可，无需引入完整工具链。[S8]

字体固定为系统字体栈，正文、主操作、辅助说明、数值读数分别定义字号／字重／行高。建议桌面常规文字13～14px，重要操作14px；触屏主要操作14～16px，避免将核心操作压到9～10px。数值采用等宽数字，中文避免不必要字间距。

 **R3.3 建有界组件API。** 至少统一 Button、IconButton、Toggle、SegmentedControl、MenuItem、Field、Slider、Dialog、TemplateCard、CandidateBar。规定 variant、size、disabled、busy、pressed、label、focus。音符格及时间轴保持专用组件，不能强行套普通按钮几何。

桌面常用控件建议34px；触屏普通按钮／工具栏点击目标以44×44 CSS px为本项目目标，可见图标可以更小。音乐画布的细小音符通过选中后放大把手、工具模式与上下文操作解决；不把44px推广成每个音符的实际时长。WCAG 2.2的最小目标准则有24px及间距／其他例外，本项目44px是产品选择。[S9]

 **R3.4 迁移顺序：** 全局播放和保存 → 作品与模板 → 轨道头与编辑工具栏 → 候选／弹窗 → 音色 → 混音。每迁移一组即移除对应旧覆盖。将 `material/studio/legou` 中仍有效规则迁入明确层；文件数与 `!important` 数量不作为唯一目标，最终每种角色要有清楚来源。

 **R3.5 固定入口。** 编排工具区提供“模板”；模板面板含单轨模板与配套模板。片段工具栏提供“模板”“创作辅助”；其中和弦进行常用可直达，后续的生成旋律等由同一入口接入。选中内容后出现复制、删除、自动生成保留项、变化。技术性吸附与精细编辑可展开。模板打开时保留作品与播放上下文，不强制切到教学首页。

“编排／乐句”作为布局选择保留。混音可从全局明确入口到达。缺少和声时，生成动作在当前面板提供“选择参考和弦”；不封锁其他功能。

 **R3.6 修正长时间轴。** 编辑区使用稳定的 `pixelsPerBar` 加横向滚动／缩放，建议默认96 CSS px／小节，编辑时最低48px／小节；全曲概览可以压缩为独立缩略条。拖动、命中、游标和缩略导航共用时间坐标转换。参数可以按屏宽选择默认值，不能因为歌曲变长自动让所有音乐块缩没。

 **R3.7 逐页验收。** 桌面1440×900、笔记本1280×800、平板768px、手机390px及320px窄屏；正常／长中文／空内容／加载／失败／缺资源都检查。关键状态通过可见文本与适当的状态播报呈现，保存成功、失败和处理中不能只靠颜色。[S10]

## 9. R4｜保留和声意图，给生成提供准确上下文

 **目的：程序知道目标音乐块在何时面对什么和弦。前置：R3。** 

### 施工顺序

 **R4.1 为和弦片段增加可选 `harmony`。** 相对片段开始记录每个和声事件的 start、duration、rootPitchClass、quality；复杂扩展可直接记录 pitchClasses。保存进行ID、版本、参考主音及和弦名称显示所需数据。全局参考调性与这些显式和弦分开。

同一个进行的长音、四拍、分解和逐音铺开版本使用相同和声事件。普通音符仍是唯一播放事实，和声说明只为创作辅助服务。

 **R4.2 增加唯一上下文解析器。** 输入目标实例ID、目标局部范围、和声来源轨道／实例；输出按全曲位置展开并裁剪的和弦时间表。处理重复片段、跨小节、半小节换和弦、来源空档和来源重叠。多个和弦来源时明确选一个，不能把所有和弦轨混成无说明的集合。

本轮优先保存和弦片段内的元数据，再通过实例位置映射。暂不增加另一条重复存同样和弦的全局事实轨；未来独立和弦轨也应通过同一解析接口接入。

 **R4.3 约束实时处理与和声的一致性。** 和弦轨的移调会改变实际和声，解析器必须采用生效的移调且只应用一次。琶音改变弹奏方法，不把原和弦拆成一串单音和弦。全局换参考调性不会改写已明确的和弦。用户烘焙移调后，元数据同步更新或标待确认，避免双重移调。

 **R4.4 建可解释的失效规则。** 保存确认时对应的源音乐指纹。修改和弦音高／删掉关键音／移动来源实例时，将相关和声或下游生成标为待复核；改变轨道名称、音量、皮肤、画板位置不触发和声失效。指纹按有效内容计算，撤销回原内容后状态也应恢复，不能只依赖单调递增时间戳。

 **R4.5 旧工程与手工和弦。** 没有和声说明时，允许用户对指定范围明确选择进行或逐段填写和弦；可以提示候选识别，但未确认的自动猜测不作为生成依据。本轮不要求复杂多声部和弦识别器。

 **R4.6 处理复制与共享。** 复制和弦片段保留相对事件；复制整轨重映射内部引用。旋律片段多个实例面对不同和声时，默认“为当前实例创建独立变化”，共享更新需要显式选择并显示影响实例数。删除来源保留已经生成的音符，并显示来源不可用。

```json
{
  "harmony": {
    "version": 1,
    "events": [
      {"start": 0, "duration": 3840, "rootPitchClass": 0, "quality": "major"},
      {"start": 3840, "duration": 3840, "rootPitchClass": 7, "quality": "major"}

```

### 保存点条件

进行语义从生成、模板应用到保存重开贯通；目标实例拿到正确时间范围；元数据与已修改的声音不一致时可见，且不会自动改别的音轨。

## 10. R5｜统一模板与配套创作配方

 **目的：用户一按即可铺出可继续编辑的音乐，模板之间能配合。前置：R4。** 

### 施工顺序

 **R5.1 整理已有目录。** 保留现有模板／音色ID及原内容。分类至少包含鼓点、和弦进行、贝斯、旋律、伴奏、整段配方、完整工程。鼓组表示“每行发出什么声音”，鼓点模板表示“何时敲哪些角色”，两种数据分开。

模板元数据包括ID／版本／类型／角色／长度／参考调性／和声／建议速度区间／资源依赖／来源与许可／适用说明。没有依据的标签与评价不写成客观排名。

 **R5.2 鼓点使用角色映射。** 底鼓、军鼓、闭镲等角色映射到所选鼓组的具体行；映射缺失时列出缺什么，用户选择替代或跳过，不把某个数字音高自动当成所有鼓组都存在的同一鼓件。

 **R5.3 模板一套应用逻辑。** 预听与应用共用同一份已冻结的候选。单轨可新增片段、替换明确范围或新建轨道；配套模板可一次新增若干轨道并放到指定小节。默认新增保护原稿；替换要显示影响轨道、范围及共享实例数。遇到冲突／空间不足／缺资源，在应用前整体验证。

一套配方应用为一个事务：成功全部写入，失败保持原状，一次撤销全部撤回。工程保存实际音符、和声和已用配置，目录未来升级不改变旧作品。

 **R5.4 制作8套起步配方。** 这是内容制作范围，不要求每套使用完全不同引擎；验收关注音乐角色和编排方法具有明显差异。

| 配方方向 | 最小材料 | 应体现的差异 |
|---|---|---|
| 清楚流行四拍 | 四和弦、基础鼓、根音贝斯、旋律节奏骨架 | 简明句法与易改旋律空间 |
| 柔和电钢／Lo-fi | 七和弦、稀疏鼓、轻摆动贝斯 | 稀疏、延音与力度层次 |
| 电子舞曲 | 四拍底鼓、短和弦、节奏贝斯 | 稳定拍点与音符短长配合 |
| 半拍流行 | 半拍军鼓、宽阔和弦、简洁低音 | 与四拍型有清楚密度和重心差异 |
| 轻摇滚／动力型 | 推动型鼓、简洁和声、低音重复 | 较明确的重复动机与转段 |
| 五声音阶轻快型 | 对应和声、拨弦伴奏、少量鼓点 | 易于改写的旋律轮廓与留白 |
| 卡农式分解伴奏 | 八小节进行、分解织体、可选低音 | 连续和声与旋律独立空间 |
| 简约问答式乐句 | 8小节伴奏、前后呼应动机、结尾方案 | 句子重复、回答与收束 |

这些名称是模板用途，不表示完整复刻某音乐流派或执行了严格古典写作全部规则。每套保留一条可移除示范旋律及一个空的旋律起点，方便立即播放或直接自己画；不增加教学步骤。

 **R5.5 目录可扩展。** 新增合法JSON模板后自动进入分类与搜索；元数据无效、ID冲突、缺资源和版本不支持给出具体结果。导入同ID同版本但不同内容时不得静默覆盖。素材包是数据，不执行包内任意脚本。

 **R5.6 听感整理。** 用现有可离线音色为每套配方实际渲染；比较默认混音的主角清晰度、密度、结尾／循环衔接和过强响度。测量只能发现静音、NaN、削波等工程问题；是否适合入库还要真实试听并记录判断。

### 保存点条件

任意已验收配方能预听、一次应用、逐轨编辑、撤销、保存重开；模板入口与手绘共存；配方有完整依赖和实际试听文件。

|---|---|---|
| R5-T01 |  **旧目录兼容** （单元＋集成）。已有全部模板与预设清单；读取、分类、应用旧模板并重开旧工程 | 原ID和音乐事实保持；新增分类不改变声音参数。 |

| R5-T08 |  **目录升级不改旧作品** （集成）。作品已应用某模板和自定义预设；更新目录、断开网络、在新实例重开工程 | 旧工程使用已保存内容／资源，声音事实保持；来源可追溯。 |
| R5-T09 |  **配方实际听感验收** （音频测量＋人工试听）。8套默认参数版本；逐套导出并在相同监听音量比较 | 无意外静音／非法值／明显削波；主角、循环与尾声有审听记录；未审听标待评。 |

## 11. R6｜实现可控旋律生成、保留项与修改提示

 **目的：铺好和弦后，可以迅速得到有结构的候选，再只变化指定部分。前置：R5。** 

### 施工顺序

 **R6.1 固定输入输出。** 首轮支持4和8小节、单声部主旋律；输入包括目标实例和范围、已确认和声、节奏模板或已有节奏、音域、循环／收尾偏好、保留项和seed。输出为最多3个候选的实际音符、解释、生成来源和约束检查结果。

`generateMelody(context, settings, seed)` 保持纯计算，不读DOM、不修改工程、不接网络。候选确认由统一命令应用。算法中的声部角色采用显式的track.role（如melody、bass、chords、drums、texture），由用户或模板设置；旧工程不确定时保留unspecified。角色不能由音色名称猜测，同一钢琴可以作旋律或伴奏。

生成应针对目标音轨的实际发声音高计算；目标轨若已有移调，写回普通音符前进行相应逆变换，并检查原谱音域，避免结果再被移调一次。影响音高关系的处理不能被悄悄关闭；无法兼容的组合给出明确选择。

 **R6.2 分层生成。** 先用节奏模板或已有起音／时长形成骨架；再按整句轮廓和和声确定少量落点；在落点之间加入调内连接、重复、休止及受控的半音趋近；保留动机并改变结尾；最后检查整个时值跨过的和弦。风格规则用权重和明确条件表示，不能把所有非和弦音当错误。

底层可以用有限候选搜索或束搜索，先限制音域、候选音数与路径预算，再评分。初始实现目标为有界、可解释、可取消，不引入训练／大模型服务。三个候选应在允许变化的音高、节奏或装饰路径上有区别，不能只改音量或重新分配ID。

 **R6.3 固定随机性。** 音高、节奏、装饰采用可独立复现的随机分支；保存seed、生成器版本、模板版本和有效输入hash。随机ID只用于对象身份，不能左右生成音乐。需要微时移时保存独立演奏种子；旧工程沿用旧规则保持已存听感。播放始终读取最终音符。

 **R6.4 加“生成时保留”。** 支持保留音高、保留节奏（起音与时长）、全部保留及锁定时间范围。范围保留还包括休止和音数，不能偷偷往空隙加音。临时保留项仅存在候选会话；用户确认后随作品保存。锁定只约束自动生成，直接手动编辑按用户意图生效，并同步更新对应保留值与依赖。

重新生成时保留原已锁定音符ID；新增音符使用新ID。全部锁住则返回“没有可变化内容”；约束只容许1～2版时如实展示，不能强行给出三份重复结果。

 **R6.5 先做四个有用动作。** 生成一句、保留节奏换音高、保留关键音改连接、只改结尾。每个动作都明确影响的片段／实例与范围。更复杂的段落变化留给R8。

 **R6.6 加就近解释。** 结构支点、有条件变化、装饰空间是当前和声／风格下的建议标签，附一句理由和可选替代方向。不能推断时显示“暂未分析／参考不足”。用户选择某个音才展开细节，避免常驻大面积说明。保留标志与建议标志独立，不能把建议转成禁止手改。

 **R6.7 预听与过期保护。** 默认在该实例所在范围连同伴奏试听，目标旧内容应被候选替代，避免新旧旋律叠放。另可单独听候选。预听不写作品、不增加历史；应用后一次撤销。候选生成或试听时若原稿改变、上游和声变化、目标删除或用户切作品，取消过期结果，不能回写到新目标。

 **R6.8 设实际性能目标。** 在记录过型号和浏览器的基准电脑上，4小节3候选的纯计算p95目标≤200ms；手机目标≤500ms。指标为待测目标，当前性能仍待验证。超标先缩小搜索、分片和缓存，必要时再用Worker；所有情况下取消操作应迅速反馈，播放调度不等待生成完成。

### 保存点条件

合法和声输入下生成可编辑内容；保留项逐字段兑现；候选可比较、解释有依据；原稿、当前实例及共享范围受保护。自动检验与实际试听都留有记录。

| R6-T07 |  **限定范围局部重写** （集成）。4小节已有内容，仅选最后一小节；执行只改结尾与仅改连接 | 范围之外逐字段不变；目标内尊重保留项；一次撤销恢复整次改动。 |
| R6-T08 |  **解释可追溯** （单元＋人工）。已知和弦内音、经过音、邻音、跨界音与无参考内容；打开各音解释并改变上游 | 理由对应真实输入；失效后更新或标未分析，不沿用无效标签。 |
| R6-T09 |  **候选取消与试听现场** （浏览器＋音频）。原曲播放在非零位置，打开生成候选；比较多版、停止、取消、关闭 | 原作品hash和历史不变；返回目标／位置／播放状态遵从合同；无重复发声。 |
| R6-T10 |  **异步过期结果隔离** （集成＋浏览器）。延迟候选生成并让目标或和声改变；旧任务晚完成，随后尝试应用 | 过期任务被丢弃或要求重算；不能覆盖新内容、其他作品或错误实例。 |

## 12. R7｜节奏、贝斯与伴奏共同工作

 **目的：其他声部围绕已有音乐配合，避免各自随机。前置：R6。** 

### 施工顺序

R7.1 把节奏作为独立对象处理：起音、时长、力度、休止、强弱位置与角色。鼓点生成先使用已验收模板变形，保留该风格指定的核心拍点，允许调整可变底鼓、镲片、轻击和句尾。支持只修改某个鼓件、只改最后一拍、变稀疏／密集。

R7.2 核心拍点属于配方偏好；用户“生成时保留”的鼓点才是绝对约束。用配置区分直拍、半拍、四拍底鼓等，不给所有风格套同一个军鼓位置。Swing、微时移和力度分开控制，默认不重复应用。

R7.3 贝斯输入至少包含明确和声，选配底鼓参考。先生成根音等支点，再连接下一和弦；支持“对齐底鼓”和“与底鼓呼应”两种策略。没有鼓轨时仍可按和声生成，不能为了流程完整强制用户先做鼓。

R7.4 伴奏输入读取主旋律活动范围和配方节奏；提供长音、轻弹、分解等方式，选择“承托／呼应／同拍加强”。密集主旋律处可减少伴奏活动；空白处可填入短句。互相避让与共同着力都属于可配置策略。

R7.5 组合生成采用固定单向依赖，避免同时相互等待。例如一次任务选择“和声＋底鼓 → 贝斯”，生成后再以“和声＋旋律 → 伴奏”。来源修改时只标记依赖变了，不自动循环重算所有轨道。任务参数明确记录采用的上下文快照。

R7.6 多轨候选一次预听、一次应用、一次撤销。音符角色／保留项、过期检查、资源解析复用R6/R5机制，不另建第二套候选系统。

### 保存点条件

鼓、贝斯、伴奏能分别或组合生成；能尊重已写内容与各自保留项；改变一个声部不意外重写其余声部。实际效果在同一套伴奏中审听。

|---|---|---|
| R7-T01 |  **风格化鼓型与局部变化** （单元＋音频）。几种节奏配方及已保留核心鼓点；只改镲、只改最后一拍、调密度 | 保留内容不变；目标鼓件／范围之外不变；配方主要重心可辨。 |

## 13. R8｜乐句变化、8～16小节编排与混音收口

 **目的：已完成的小段能发展成完整作品，同时保持可控和可理解。前置：R7。** 

### 施工顺序

 **R8.1 先做局部变化。** A′保留主要节奏或动机，改变允许范围；回答句参考前句节奏／轮廓，控制方向和结尾；收尾模板减少活动或安排明确落点。用户可以指定保留开头、保留节奏、保留收尾。所有结果继续使用普通片段。

 **R8.2 再做整段编排配方。** 最小支持8／16小节。输入为用户选中的材料组及开始小节，输出为片段实例的排布和少量显式新增变化。提供几种节制的布局配方，例如“先伴奏、后旋律”“A—A′—B—结尾”“循环前留一拍”。不生成固定教学路线，也不自动判断所有作品都需要前奏或结尾。

配方主要改变出现位置、进入／退出与独立变化片段，避免同一轨道的实例重叠。需要每段不同声音时使用明确新音轨，暂不引入片段级独立音源系统。需要每段不同力度时写入对应独立片段的音符力度；本轮不为此暗中加入未经设计的全局自动化系统。

 **R8.3 复制规则复核。** 简单重复允许共享引用；A′与生成的新句子默认独立。多轨复制保持相对时间、来源映射和资源身份；整轨复制保留内部共享，不连接到原轨的可变片段。

 **R8.4 基础混音收口。** 继续保留音量、声像、静音、临时Solo、现有效果与总输出。可提供“应用配方建议混音”，先预听后一次应用，说明会影响哪些轨道；不把它标为自动母带。混音控制始终能随时进入，不要求按创作次序走到最后才开放。

 **R8.5 导出与复杂度边界。** 16小节模板扩成更长作品时，按统一范围导出。现有WAV单次时长上限若仍为3分钟，超限明确提示或显式分段，不静默截断；MIDI通道及采样资源限制沿用明确文案。结构支持多少轨与某设备能同时播放多少轨分别验证。

### 保存点条件

同一组材料能形成8～16小节，并能追溯哪些是重复、哪些是独立变化；混音建议可撤销；保存重开和导出仍成立。

| 编号 | 测什么／怎样测 | 通过标准 |
|---|---|---|
| R8-T01 |  **A′保留与变化** （单元＋浏览器）。选择已有4小节材料并保留部分内容；生成A′与应用 | 原A片段完全不变；A′有独立ID与实质差异；保留条件全部满足。 |

| 音频 | 全曲／片段／当前小节／多轨／候选、非零起点、循环、停止、WAV/MIDI范围 |

### 15.4 设计与听感的证据范围

截图证明对应页面状态，无法证明音频延迟或长期稳定。DOM几何测试证明元素位置／尺寸，无法完整替代视觉验收。离线渲染证明实际生成音频，无法证明手机实时负载。声音合法和可复现，也不能推出每个候选都符合用户审美。

未进行人工听评时必须写“已渲染／尚未审听”。未使用实际手机时写“触屏模拟通过／真机待验”。不为追求统一的全通过文字删去这些区分。

## 16. 范围控制与实施纪律

### 16.1 实现决定

| 问题 | 本计划默认决定 |
|---|---|
| 是否加入教学模式 | 不加入；只保留模板、工具、就近输入提示与音乐关系说明。 |
| 是否强制先和弦再旋律 | 不强制。只有依赖和声的具体生成动作需要明确和声来源。 |
| 新工程长度如何统一 | 支持1/2/4/8/16小节片段，所有写入与读取引用同一合同。 |
| 是否换前端框架 | 保留现有技术；先统一职责与接口。 |
| 是否重写音频引擎 | 保留现有发声与调度核心，以回归保护。 |
| 是否全自动更新下游音乐 | 只标参考已变化；用户确认才重生成指定范围。 |
| 是否把“结构支点”禁止修改 | 不禁止。用户的自动生成保留项才是算法硬约束。 |
| 是否按模板数量验收 | 以有效配套、可编辑、可撤销和实际试听为主，数量只是内容范围。 |
| 是否为每个功能再建一个页面 | 常用操作就近展开，复用目录、候选和属性面板。 |
| 是否新增复杂和弦识别 | 本轮优先保存明确和声与手动指定，识别只能作待确认辅助。 |
| 是否保证所有设备64轨实时播放 | 不作该保证；分开验证结构容量与具体设备性能。 |

### 16.2 遇到问题的处理路径

先还原产生问题的最小输入和成功路径，确认失败属于哪个合同；修正责任模块及所有调用者；补一条覆盖同类情况的用例；重新运行本批和已完成批次的相关成功路径。避免针对某个页面再加一条与底层相冲突的特殊处理。

如果本批被阻断，可以继续做不依赖该结论的文档或测试准备，主线不能将其记为通过后进入依赖它的下一批。用户界面不需要因此新增“待解锁功能”状态。

### 16.3 本轮最终交付清单

完整源代码和固定提交；直接可运行的HTML；同源开发／验收启动方式；模板与配方数据；资源来源与许可；工程格式和迁移说明；设计系统与生产组件样例；每批保存点；实际验收JSON、日志、截图和音频；旧工程与最终固定成功路径夹具；清晰的已完成／限制说明。

 **最终成功路径固定为：模板快速铺底 → 自由编辑 → 指定上下文生成 → 保留喜欢的部分 → 局部变化 → 编排混音 → 多作品保存与重开。** 

这条路径用于验收实施成果，不作为产品中的教学流程或强制操作顺序。
