## 1. 时间编辑：保留连续音，不人为切出新的起音

原反例是八小节块里一个从第5小节延续到第8小节的长音，清空第1小节后变成三次发音。本版对完全不相交的清除保持原内容与身份，编译前后都是一次相同发音；这类实际没有改动的命令不增加撤销。

清除遇到穿越范围的长音时，保留选区前后两侧及其中的静音。删除时间时，将删去的时间并拢；同一持续音的前后两侧连接成一个事件，其余音符只进行规定的平移或截取。和声事件、用户保留范围与共享实例一同处理，生成来源保留且标为需要重新复核。

关键调整是允许音乐块使用**1—16之间的全部整数小节数**，例如删除八小节中的一小节后保留一个七小节块。不会再为了满足1/2/4/8/16集合，把残段拆成4+2+1并额外起音。音频引擎没有为修复而增加另一套时间轴或拼音规则。

验证包括1、2、3、5、7小节删除，清除/删除跨界长音，共享外部引用、Swing与轻微演奏时间、移调、和声、保留项和全部八小节区间72种组合。生产页面也实际下载了七小节持续音作品并重新校验。

**兼容边界：**本版继续读取既有v3作品，结构版本不变。包含3/5/6/7等新块长的作品需要2.2.1或以后打开；旧2.2会拒绝它们的长度。WAV/MIDI输出不受这个验证器限制。此变化已写进应用源码文档与交付说明。

## 2. 模板集合与旧示例完整迁移

顶部“音乐模板”打开大库。主工作台不再显示常驻窄托盘；库内有全部、本次待用、收藏、最近、正在用，并保留组合、节奏与乐句、示例作品类别。

新增LibraryCollections统一处理两个旧存储键。旧收藏与待用去重迁移一次，后续删除不会被旧键重新带回；主动清空保持为空。无法找到的素材ID保留并说明待补资源。音乐域与音色域分别筛选。

“正在用”基于实际放入编排的内容、和声与来源记录；未放置草稿不计入。原来没有来源标记的模板只通过精确音符与长度匹配恢复识别，不按名字猜测。

5份原有示例已经有可见入口。可以先试听，再明确新建为独立作品；不允许作为普通块拿取或加入批量，当前作品按原有项目管理流程先保存。

**测试方法说明：**集合合并和错误条件使用单元测试控制的存储对象。新建示例页面测试32仅在存储边界使用明示内存适配器，验证原作品与新作品身份和调用顺序；它没有证明真实IndexedDB刷新。其余页面测试使用实际生产DOM与音乐处理。

## 3. 声音选择、参数和资源各有一个入口

从轨道或画板的本轨音色进入：当前声音摘要→选择音色→试听→使用。声音选择固定原音轨，音符/节奏保持；删除目标后禁止使用；一次采用可撤销。

“调节与导入”里现在是**调整当前声音**与**声音资源与导入**。参数页只显示当前声音的明亮度、起音、释放、效果，以及当前采样适用参数。这里没有音色卡片、分类、搜索和第二个完整库入口。

资源管理集中录音、导入音频、导入音源包、备份和鼓组。原资源管理的音色/模板页签重定向同一个库；管理鼓组时也没有暗藏的旧声音浏览页面。旧渲染函数可供历史测试使用，不再被当前参数入口调用。

实际展开了深层面板，使用真实滑杆核对修改与撤销，并检查资源页面的全部可见导航。

## 4. 批量放置：先看清、听清，再一起写入

在模板详情加入多块材料，选择“接着放”或“一起放”。计划面板包含起始小节、顺序、每块长度、音高处理、目标音轨和总范围，并在真实编排位置显示投影。

| 方式 | 当前行为 |
|---|---|
| 接着放 | 在一条已有同类音轨，或一条明确的新轨中按顺序排列；可调整先后顺序。4+4+2从第5小节开始，明确占第5—14小节。 |
| 一起放 | 同一起点，每块可指定已有匹配音轨或新增；建议先复用空闲匹配声部，不静默覆盖已有内容。 |
| 试听 | 试听整组，或连同作品听；实际文档、范围和最后采用的是同一个冻结计划。 |
| 放置 | 单块拖放继续直接放入；批量点击/原生拖动先固定位置，检查或试听后“确认放入”，一次提交、一次撤销。 |
| 冲突 | 提示占位、轨道类型、容量或原稿变化。相关修改需要重新检查；其他轨的无关改动通过候选补丁保留。 |
| 取消 | Esc/取消/失焦统一停止候选、移除轮廓并恢复大库浏览现场；无效外部事件不能误用旧计划。 |

已有轨道保留自己的声音，新轨使用模板推荐声音。可以选择保持模板原调，或按当前主音移调；界面明确说明同主音不代表所有和声都兼容，需整体试听。声音、示例作品和整套组合不混入单块批量。

超出原歌曲长度的候选先提供真实的预览滚动范围，原来音乐块宽度和时间坐标保持；确认后才增长作品。短窗口计划面板可以滚动，底部试听、确认与取消可达。

## 5. 原有能力与皮肤保持

音高尺仍固定左侧，横向滚动不丢失；尺上拖动与“浏览”上下拖动只改变音域，不改音乐或撤销。安全长度、尾部收短、空白音乐块保护、循环与时间编辑撤销/重做继续通过。

原有76个音色和26套组合分别实际渲染，共102项。55份旧声音对照都处于1个16位量化单位以内，其中31份完全一致。此处是音频数据检查，没有代替主观听感评价。

视觉基础tokens和现有组件保持。新增集合页签与批量计划使用相同字体、浅边框、珊瑚主动作和音乐色。没有新建播放器布局、教学步骤或新合成引擎。

## 8. 如何复核与交付

在GridTone目录执行 `npm test`、`npm run build`。安装requirements-test.txt里的Python依赖及Chrome后，`CHROMIUM_PATH`可指定浏览器；`npm run verify:engineering`实际运行当前工程测试，包含600秒持续验证。视觉人工结论仍须按新生成页面复看，脚本不会自动伪造review.json。

交付拆成小型应用ZIP与源码ZIP，避免重复装入大批WAV而影响下载。原始音频数值、哈希、26份工程与再生成脚本均保留。源码包含代码、素材数据、许可、测试、文档、最终证据和本地保存点；下载到的实际ZIP会独立解压、逐文件核对、重新执行394项测试并重建，和应用文件逐字比较。最终结果见包外的 `Legou_2_2_1_Verification.json`。

本版继续以明确的作用对象、范围、试听与确认组织创作。旧2.2和2.1报告作为历史保存，本轮全部数字来自实际重新执行，不沿用旧的“通过”代替验证。
