# 乐构模板与合成音色扩充调研

日期：2026-09-19。性质：只读研究与建议；未安装第三方引擎、未导入素材、未修改应用、未推送 GitHub。本文件是本轮唯一新增产物。现有界面打磨的未提交修改保持原状。

## 结论

建议采用“合成参数为主、精选短采样为辅、素材包按需加载”的混合路线。先整理发现入口，再做小型听评样板，通过后批量扩充。引擎、音色预设、音乐模板分别建账；下载数量和参数组合数量不能代替听感差异。

商业设备用于确定声音目标，不直接搬运厂商波形或默认预设。代码授权、预设授权、波形/录音授权、名称使用分别核对。此处为来源筛选，不构成对所有素材的最终发行许可确认。

## 当前代码核查

- `catalog/studio.json`：Classic Studio 包有29个预设，分为13个模拟合成、12个四运算器FM、4个电子鼓组；这个包没有音频采样资源。数字不包括全部历史预设。
- 同包55个音乐模板：鼓39、贝斯6、和弦4、旋律6。39个鼓模板里有9个GMD摘录，以及6个原创鼓点家族的30个版本。
- `catalog/studio-families.json`：36个家族，包括13声音、17节奏/乐句、6组合家族。和弦乐句只有“反拍轻弹”“往返分解”两个家族，各2版本。
- `src/music/progressions.js:8`：另有24组和弦进行，4种弹奏方式、3种音符排列；`src/views/composer.js:34`在独立的和弦工具里显示4类分组。应先把这批已有能力接到大库，同一进行的移调不复制成新模板。
- `scripts/studio-content.py:131`：现有“反拍轻弹”反复C大三和弦，“往返分解”使用固定C大三和弦音；基本/收尾版主要差在最后一小节留白。这解释了和弦材料的单一感。
- `src/audio/studio-engines.js`：原生Web Audio模拟合成、FM4、电子鼓。只借用了AMY部分控制曲线，并未接入AMY完整运行时；现有FM4不能直接读取DX7/SEQTRAK预设。
- `src/catalog.js:71`、`src/model.js:9`：当前采样资源为内嵌WAV Base64，资源上限24 MiB。播放侧已有按轨道需要解码和缓存（`src/audio.js:334`）。外部扩展包索引、资源散列去重和压缩容器需要单独实现。
- `src/audio/sample-banks.js`：已有用户点击后下载特定VSCO样本并转为轻量WAV的路径；可借鉴流程，不增加本轮不需要的真实乐器库。
- `src/audio/instruments.js:101`：已有按根音选择最近样本的多采样播放器；目前没有持续音循环点和力度分层。长音垫采样需要补充这些能力或改用合成。
- `src/model.js:5`：当前小节固定为3840 tick，即4/4。第一批素材限定4/4，可在其中使用三连/切分；真正3/4、6/8等拍号支持单列工程任务。

## 音色候选

### 1. AMY：优先做技术样板

[官方仓库](https://github.com/shorepine/amy)采用MIT代码许可，支持Juno式模拟合成、DX7式FM、PCM、波形振荡器及浏览器构建。项目有音频采样时钟驱动的实时/离线渲染能力。这些是上游能力，尚未在乐构内验证。

适合：复古厚垫、合成铜管、弹性低音、FM电钢、玻璃拨弦、数字钟声。复用成熟引擎比继续把有限的旧参数微调成大量预设更有价值。

风险：适配宿主时钟、多轨隔离、停止清理、复音控制、离线WAV、单文件离线载入。音色库与内附采样仍需逐项查来源，MIT代码许可不能自动替代内容授权。

公开仓库树查询时，`docs/amy.wasm`为4,839,387字节，`docs/amy.js`为75,612字节。仅为当时仓库构建文件体积，不是乐构集成包、压缩传输或内存实测。可做专门裁剪构建，效果需实测。

### 2. DX7 / Dexed / MSFA：经典FM专项备选

[Dexed官方](https://github.com/asb2m10/dexed)说明整体GPLv3，核心MSFA保留Apache 2.0。当前乐构代码为MIT；直接整包嵌入需要遵守其许可，不能简单当MIT组件搬入。

[webdx7](https://github.com/webaudiomodules/webdx7)已有浏览器AudioWorklet/WASM示例，包装MIT、MSFA Apache 2.0。但README明确是work-in-progress并保留旧浏览器兼容技巧，适合作原型参考，未经现代浏览器验收不直接投产。网上SYX银行另查作者许可，避免把可下载等同可重新分发。

### 3. AKWF：体积很小的声音原料

[作者仓库](https://github.com/KristofferKarlAxelEkstrand/AKWF-FREE)、[许可](https://github.com/KristofferKarlAxelEkstrand/AKWF-FREE/blob/main/LICENSE.md)：CC0，原版为600采样点、16bit、单声道的单周期波形。每个波形的音频主体仅1200字节；100个约120 KB，不含容器、元数据及引擎。

适合：数字主音、复古游戏声、空心/鼻音低音及基础波形以外的质地。它们是振荡器原料；需要包络、滤波、力度响应、限带处理和精选配方才能成为好用预设。静态单周期不等同于完整动态波表合成器。

### 4. Surge XT：作为音色制作工具优先

[官方仓库](https://github.com/surge-synthesizer/surge)是GPL3的成熟桌面混合合成器，曾是商业软件。[官方FAQ](https://surge-synthesizer.github.io/faq/)明确允许使用其生成的声音/采样分发或商业使用，包括从工厂预设开始制作。

可在制作阶段设计声音，导出少量多音高干声，作为可选音色包。这样用户端无须运行整套桌面插件。第三方另下载的预设/波形仍须单独检查。局限：采样会牺牲连续调制自由；跨音区音质、长音循环、力度变化和立体声宽度需要专门听评。

### 5. Plaits：第二阶段的差异化来源

[Mutable Instruments仓库](https://github.com/pichenettes/eurorack)、[Plaits引擎源文件](https://github.com/pichenettes/eurorack/blob/master/plaits/dsp/engine/virtual_analog_engine.cc)：Plaits相关STM32代码为MIT，整个仓库还有GPL AVR项目，不能笼统标记全仓MIT。可选部分数字合成/共振算法，用于现有库较少的质感。需WASM移植和宿主适配；不作为首批关键路径。衍生产品命名遵循上游商标与命名指南。

### 商业设备参照边界

[Yamaha SEQTRAK官方](https://ca.yamaha.com/en/audio/music-audio-production/products/music-production-studios/seqtrak/)明确列出AWM2和四运算器FM两类引擎。可以用其FM电钢、Pad、Lead等声音方向做听感目标；本轮未找到允许将其工厂声音作为第三方软件素材库分发的明确许可。DX7方案也不代表SEQTRAK兼容或等同复刻。

## 808与素材体积

候选：[Michael Fischer TR-808 / TidalCycles](https://github.com/tidalcycles/sounds-tr808-fischer)，仓库附[CC0许可](https://github.com/tidalcycles/sounds-tr808-fischer/blob/main/LICENSE)。README称直接从硬件独立输出录制，116个样本。

2026-09-19读取GitHub树元数据：树SHA `85fbecf1bec32553395625ea659e2a56dfd7c0e1`，WAV合计12,639,970字节，约12.64 MB（十进制）。16种鼓件各选一个中间参数位置样本的合计为1,235,530字节，约1.24 MB。此为文件清单统计，未下载试听，也没有确认这16个就是最佳选型。发行前固定来源commit、核验文件摘要和授权链。

代表文件：BD5050、CB、CH、CL、CP、CY5050、HC50、HT50、LC50、LT50、MA、MC50、MT50、OH50、RS、SD5050。完整清单可从固定树重新生成。

建议一个小型经典808基础组，其他调音/长尾版本放可选扩展。现有8角色映射不能直接表达全部16鼓件，新增鼓组时明确映射、显示行和旧作品兼容。采样鼓的开闭镲互斥也应专项验证。

体积策略：

1. 旋律合成优先参数预设；特殊声音使用精选短采样或多采样，避免全键盘全力度打包。
2. 内置核心、扩展可选；点击试听/下载前显示包大小与本地状态。下载不自动采用，不上传作品。
3. 下载一次后本机缓存；按实际需要解码。样本以散列和稳定ID去重，并保留包版本。
4. 作品导出只携带实际需要的资源；支持完整离线备份，不能仅留会失效的远端链接。
5. 默认保留鼓高频和起音；裁掉多余静音，做安全短淡出。不可一律低采样率和单声道，镲片/立体声音垫会损失特点。
6. 当前WAV/Base64方案先控制精选资源规模。将来引入FLAC等压缩要同时设计解码、缓存、旧作品迁移与离线导出；不只是改文件后缀。

容量须分别看：传输压缩文件、磁盘缓存、解码内存、CPU复音。Base64约额外1/3。Web Audio的AudioBuffer为32位浮点；44.1kHz单声道1秒音频主体约176.4 KB，立体声约352.8 KB，不含对象/缓存开销。[AudioBuffer文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioBuffer)。以上为格式计算，不是本机性能实测。

## 节奏与和弦来源

### Groove MIDI Dataset：扩大已有来源覆盖

[Google/Magenta官方GMD](https://magenta.withgoogle.com/datasets/groove)，CC BY 4.0，真人演奏，带力度与微小时差；MIDI-only ZIP为3.11 MB，连音频版本4.76 GB。只需前者的精选片段。

当前已经从3个源文件截取9段；后续从不同演奏、风格和节奏重心扩展，按原始文件+小节范围去重。保持来源、授权、摘要、原BPM和映射损失说明。GMD主要是真人鼓演奏，不当作House/Techno/Trap完整电子节奏库。

### SHLD free-midi-chords：和声扩充首选参考库

[作者仓库](https://github.com/ldrolez/free-midi-chords)明确MIDI文件采用MIT，当前介绍190组进行/调及大量移调、节奏版本。大文件数包含重复关系；应提取级数、和弦性质与节奏结构，与乐构现有24组先做对照。

已有I–V–vi–IV、卡农式八和弦、ii–V–I、六二五一、王道式、自然小调等无需再作为“新内容”重复加入。优先补12小节蓝调、调式两和弦、不同和声节奏、借用和弦及经过和弦；这里是策划方向，具体候选需核对上游数据并做听评。

和弦进行、弹奏型、音色分别建模。例如同一个进行可以用长音、反拍短击、分解弹奏；不将每个调/每个弹奏组合铺成独立一级卡片。

### Tonal：可选构建期工具

通过Context7查询了[Progression](https://github.com/tonaljs/tonal/tree/main/packages/progression)、[Voicing](https://github.com/tonaljs/tonal/tree/main/packages/voicing)官方文档。适合和弦解析、移调、音域与连接候选校验。它提供乐理工具，不提供策展过的好听模板；已有生成器可继续复用，无须为扩目录强行引入新运行依赖。AMY未在Context7找到匹配项，已改查官方仓库。

### 暂不采用

- 厂商工厂音色/ROM：没有明确再分发许可的条目不捆绑。
- 随意下载的“免费808包”：例如[SampleRadar](https://www.musicradar.com/music-tech/samples/sampleradar-105-free-808-weight-samples)明确允许音乐使用但禁止再分发采样，不能塞入模板库。
- 批量商业歌曲转MIDI、来源模糊的鼓谱书转录：公共可见或仓库有代码license不足以证明所有音乐材料可随软件分发。
- 整个巨型音频数据集、整套桌面插件：暂不进入默认浏览器包。

## 分类提案

保留音乐与声音两个工作域。一级为用途，二级为该用途的音乐类别，最后才是具体家族。收藏/最近/待用是集合，独立于分类。

| 域 / 一级 | 二级示例 | 详情里的版本或参数 |
|---|---|---|
| 音乐 / 鼓点 | 四拍舞曲、碎拍、Hip-hop、放克灵魂、拉丁、过门 | 基本、推进、收尾；速度建议 |
| 音乐 / 和弦进行 | 流行、七和弦、爵士回转、小调、蓝调、调式氛围 | 调性、音符排列、弹奏方式 |
| 音乐 / 伴奏节奏 | 长音铺底、反拍短击、分解、切分拨奏 | 选参考和弦；短/长版本 |
| 音乐 / 贝斯 | 根音承托、八度推进、切分、行走、滑音型 | 目标音域、和声参考 |
| 声音 / 低音 | 圆润模拟、共振酸性、弹指FM、深沉Sub | 明亮、尾音、运动宏控 |
| 声音 / 键盘与和弦 | FM电钢、复古铜管、短促Stab、数字键 | 同家族少量实质版本 |
| 声音 / 音垫 | 复古宽厚、数字玻璃、流动纹理 | 起音、宽度、运动 |
| 声音 / 鼓组 | 经典808、紧致电子、金属数字等 | 鼓件预览；下载大小 |

音色的“FM/模拟/波形”作为辅助标签，与明亮/柔软/颗粒等标签并列；默认不用技术引擎名当唯一入口。小分类点选即可过滤，保留路径与结果数，避免反复打开多层文件夹。

角色与风格支持多标签，同一模板只存一份。家族里的轻微变化归为变体。试听固定目标，支持单听和连作品听；切类别恢复搜索/滚动/选择，找不到ID明确提示。

## 差异性与质量门槛

- 鼓点：对比底鼓/军鼓位置、重音、切分、律动、密度与句末结构；整体移速、简单加减镲片优先标为变体。
- 和弦：归一化主音后比较级数、性质和每个和弦持续长度；移调、转位、循环换起点通常同族呈现，循环起点仍保留其听觉重心差异。
- 音色：同一角色使用相同短句、多个音高与轻/中/重力度，分别听干声和建议效果。对比起音、频谱、动态、尾音和调制；调大音量或混响不算独立家族。
- 先用结构指纹找重复，再做听评；不能以不同JSON哈希或频谱距离单独证明“好听”。
- 听评包括单轨辨识、进入同一伴奏的适配、连续循环与衔接、音域极端、鼓贝斯低频冲突。自动检查含爆音/削波、起止点击、静音意外、长音截断、停止清理、离线导出一致性。
- 每项必须有“相较已有哪个条目，新增了什么用途”的一句话说明。未通过的保留为候选，不计入交付数量。

第一批目标建议：在整理现有内容后净增12—16组和声关系、10—12个鼓点家族、8—12个伴奏/贝斯家族、约24个精选合成音色和1个808基础组。数量是上限方向，按差异性与听评淘汰，不硬凑。新预设用新ID和引擎版本，旧作品声音定义保持。

## 执行计划（待确认）

1. 建内容清单与差异矩阵：已有材料、候选、来源授权、适用风格、重复组；先把24组进行接入统一分类的设计方案。
2. 小样板：12个音色、8个真正不同的鼓点、6组和声/伴奏对照；每类与旧库A/B比较，标注来源和体积。这里同时做AMY最小实时/离线适配实验，判断是否值得进入主程序。
3. 扩充数据与分类：复用现有目录、来源账本、固定目标试听与一次撤销；进行/弹奏/音色独立组合。切换主音不能被当成自动适配整首作品和声。
4. 资源策略：核心零下载可用；小808可内置或随离线包，较大采样包显式按需安装。确定文件、缓存与内存预算后再决定压缩格式和上限调整。
5. 验收交付：旧作品音频对照、模板结构去重、渲染/停止/导出回归、冷/热载入、断网重开、多轨CPU与内存、键盘导航/小窗口分类。听评与工程验证分别报告。
