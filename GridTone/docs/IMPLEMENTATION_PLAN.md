# 一、为什么采用这个施工顺序

这次应当沿着一条能够逐步验证的主线施工：

> **先保证写出来的东西正确、能保存，再保证入口和组件一致，然后让模板及算法建立在可靠的数据关系之上。**

具体顺序如下。

| 批次 | 做什么 | 做完后解决什么问题 |
|---|---|---|
| **R0：固定基线** | 整理当前代码、已知问题、测试入口和样例工程 | 实施者清楚哪些已经存在、哪些需要修，能够恢复原版本 |
| **R1：统一基础规则** | 长度、时间运算、修改事务、复制、播放范围 | 画板允许的内容能够保存重开，操作名称与结果一致 |
| **R2：独立保存作品** | 多作品管理、自动保存队列、恢复点、旧数据迁移 | 不同灵感互不覆盖，随时能够回来继续写 |
| **R3：设计系统与入口** | 统一组件、样式来源、响应式、模板入口和长时间轴 | 后续功能直接使用成熟组件，常用模板不再埋得太深 |
| **R4：和声上下文** | 保存和弦时间表，解析实例位置及生成依赖 | 算法知道这一段实际面对什么和弦 |
| **R5：配套模板** | 整理目录，制作成套配方，统一预听和应用 | 一按就能铺出可继续修改的音乐底子 |
| **R6：旋律生成与提示** | 多候选、保留音高或节奏、局部重写、理由说明 | 能快速得到旋律，并控制哪些内容变化 |
| **R7：声部联动** | 鼓型变化、贝斯生成、伴奏与旋律配合 | 各条轨道围绕同一套音乐关系工作 |
| **R8：发展与编排** | A′、回答句、结尾、8～16小节结构、基础混音 | 从一个小段发展成完整的音乐 |
| **R9：最终验收与交付** | 全流程回归、视觉和音频检查、独立重建 | 交付包与实际验收过的代码对应 |

**默认串行推进。**当前批次通过后，提交保存点，再进入依赖它的下一批。模板内容整理、组件样例、测试数据可以提前准备；工程格式、保存、播放和命令入口集中在一条主线上维护。

# 三、R1：统一工程规则和音乐修改方式

## 实现目的

先消除“界面能做，保存后不能打开”以及“操作结果与名称不一致”的问题。

这批优先修复审查中已确认的两处矛盾：16小节片段的读写规则不同，以及细网格音符减半后反而变长。:chatgpt-content-reference{index="1"}

## 施工内容

### 1. 统一片段长度与时间运算

本计划建议完整支持：

> **1、2、4、8、16小节。**

界面、模板、修改命令、保存和读取，全部引用同一份定义。

时长运算与画板吸附分开。例如：

| 操作 | 规定结果 |
|---|---|
| 120 ticks减半 | 60 ticks |
| 80 ticks减半 | 40 ticks |
| 240 ticks减半 | 120 ticks |
| 1 tick减半 | 保持1 tick，并提示已到最短 |
| 拆分一个音符 | 两段总时长等于原时长 |
| 加倍后超出片段 | 明确拒绝，或让用户显式选择裁剪 |

**网格决定画音时如何吸附；时长减半负责数学上的减半。**

旧工程已经存在的小数时间不做无提示的全曲取整，避免改变原来的演奏细节。

### 2. 所有修改走统一提交路径

画音、删除、复制、移动、拉长、换音色、应用模板，统一经过：

> **确定作用对象 → 形成候选 → 检查边界 → 提交 → 记录撤销 → 保存 → 更新播放。**

一次拖动只形成一个撤销项。取消、失败和实际没有变化的操作，不增加撤销记录。

### 3. 补齐整条音轨复制

整轨复制应包含音色、混音、片段和编排位置，并重建对象ID。

原轨内部两个实例共享同一个片段，复制后，新轨内部仍保留这种共享关系；新轨与原轨的可修改片段相互独立。

### 4. 固定播放与导出范围

全曲、片段、当前小节、所选轨道和候选试听，始终显示明确目标。

默认全曲导出尊重作品静音，忽略临时Solo；导出当前试听范围需要明确选择。全局停止结束主播放、独立预听和等待中的启动任务。

## 验收标准

所有可选长度完成“创建—修改—导出—重开”；细网格运算准确；复制关系正确；失败操作零写入；浏览音域、缩放和换参考调性不改变已有音符。

**保存点：`plan-r1-contracts`。**

# 四、R2：可靠保存多个灵感

## 实现目的

让“记录灵感”成为可长期使用的能力。

目前存储主要是一个 `autosave` 和有限恢复点，独立作品管理尚未完整建立。:chatgpt-content-reference{index="2"}

## 施工内容

作品按各自ID保存，提供新建、打开、改名、复制为新作品、下载和删除。列表先保持简单：名称、修改时间、轨数、小节数和可选备注。

恢复点也按作品分别管理。A的修改和恢复不能覆盖B。

这一批要特别处理自动保存的异步问题：

> **保存任务建立时，就绑定作品ID、内容快照和版本。**

不能等任务真正执行时，才去读取当前全局作品。否则，快速从A切到B时容易发生错误归属。

界面显示“已保存”，需要等数据库事务完成。IndexedDB提供事务完成和终止机制，可以据此区分成功与失败。:chatgpt-content-reference{index="3"}

## 验收标准

创建A和B，反复切换、修改、刷新、重开，两份内容保持独立。人为延迟保存、制造失败、同时打开两个标签页，也不能静默覆盖作品。

旧autosave迁移一次，保留原始备份；再次启动不会重复生成同一个作品。

**保存点：`plan-r2-projects`。**

# 五、R3：统一设计系统，把模板放到手边

## 实现目的

让后面的模板、候选和生成面板从一开始就使用一致的组件。

当前已有设计文档、tokens和共享按钮，但历史样式覆盖、组件参数和最终页面还没有完全收拢。:chatgpt-content-reference{index="4"}

## 施工内容

### 1. 建立唯一的语义参数

统一主文字、辅助文字、画板底色、控制层、选中、焦点、危险操作、控件高度、间距和动效。

皮肤只修改这些语义值，页面布局和行为保持一致。可以参考Design Tokens的命名与引用方式，无需引入复杂工具链。:chatgpt-content-reference{index="5"}

### 2. 明确组件角色

同一个组件在不同页面保持同样规则：

| 组件 | 统一什么 |
|---|---|
| 普通按钮 | 主要、次要、安静、危险操作的表达 |
| 图标按钮 | 尺寸、点击区域、提示和焦点 |
| 开关 | 静音、只听、循环的状态反馈 |
| 分段选择 | 工具、模式等互斥选择 |
| 输入与滑杆 | 标签、数值、边界和错误 |
| 弹窗 | 标题、关闭、焦点、底部操作 |
| 模板卡片 | 预听、应用、选中和依赖提示 |
| 候选栏 | 比较、保留、应用和取消 |

触屏普通按钮以44×44 CSS像素点击区域为本项目目标；音符本身保持真实时值，通过选中后的把手和工具模式辅助操作。这个44像素是产品选择，WCAG的最小目标准则另有24像素及例外条件。:chatgpt-content-reference{index="6"}

### 3. 模板入口前移

编排区直接提供“模板”，可以选择整套配方或单轨材料。

片段编辑直接提供“模板”和“创作辅助”。和弦进行可以就近进入；后续的生成旋律、生成节奏和做变化沿用这一入口。

**新建后直接进入工作台。**模板始终在旁边，用户可以立刻手画，也可以立即套用。

### 4. 整理长时间轴

编辑时间轴按每小节稳定宽度显示，支持缩放和横向滚动。全曲概览可以压缩，编辑区需要保留可点击的音乐块。

### 5. 建一张生产组件样例页

样例页直接调用实际组件，展示正常、选中、禁用、加载、失败、长中文和小屏状态。以后修改按钮或字体，就有一个统一的检查位置。

## 验收标准

常用模板面板一次操作可达；片段内和弦进行最多两次操作可达。关键状态在小屏仍可见，长歌曲的单小节片段仍能选中，换皮肤不改变音符和布局几何。

**保存点：`plan-r3-workspace`。**

# 六、R4：保存和声关系，给算法提供准确输入

## 实现目的

让生成器知道：目标片段在歌曲的这个位置，实际面对什么和弦。

当前生成进行时知道和弦配方，应用后主要保存普通音符，缺少可供其他声部读取的和声时间表。:chatgpt-content-reference{index="7"}

## 施工内容

### 1. 普通音符之外，保留和声说明

例如：

```text
第1小节：C
第2小节：G
第3小节：Am
第4小节：F
```

实际数据记录起点、时长、根音和和弦类型。

长音、分解和弦、四拍轻弹可以使用同一份和声说明，分别生成不同的演奏音符。

### 2. 正确解析编排位置

和弦片段放到第九小节，旋律位于第十小节，生成器必须读到第十小节对应的和弦。

同一旋律片段在两个位置面对不同和声时，按当前位置重新生成，默认创建独立变化，避免另一处被一并改掉。

### 3. 上游变化时提示复核

修改和弦后，已有旋律保留。程序提示参考已变化，由用户决定是否重新生成未保留的部分。

改轨道名称、音量、皮肤或画板位置，不应触发这种提示。撤销和弦修改后，依赖状态也要恢复。

### 4. 检查实际移调

来源和弦轨若启用移调，生成器需要参考移调后的和声。目标旋律轨也有移调时，写回音符要避免再次叠加。

## 验收标准

同一进行的不同弹奏方式提供相同和声；重复实例、跨小节、半小节换和弦和长音跨和弦都正确；保存重开保留关系；缺少来源时明确提示，不擅自猜测。

**保存点：`plan-r4-harmony`。**

# 七、R5：把模板整理成可以直接配合的音乐材料

## 实现目的

实现你最看重的部分：**点一下就能铺出底子，之后继续自由修改。**

## 施工内容

首先保留现有模板和预设的ID、资源关系及旧作品效果，再整理为鼓点、和弦进行、贝斯、旋律、伴奏、整段配方和完整工程。

鼓组与鼓点模板分开管理：鼓组决定“发什么声音”，鼓点模板决定“什么时候敲”。同一个鼓点模板换鼓组时，应按底鼓、军鼓、闭镲等角色映射。

本轮建议先制作八套配套起点：

| 方向 | 重点 |
|---|---|
| 清楚的流行四拍 | 简明和弦、基础鼓、根音贝斯 |
| 柔和电钢／Lo-fi | 七和弦、稀疏节奏和力度层次 |
| 电子舞曲 | 四拍底鼓、短和弦、节奏低音 |
| 半拍流行 | 宽阔伴奏和较稀疏重心 |
| 轻摇滚／动力型 | 重复动机、推动节奏和转段 |
| 五声音阶轻快型 | 拨弦、留白和易于改写的轮廓 |
| 卡农式分解伴奏 | 八小节和声与连续织体 |
| 简约问答式乐句 | 前后呼应、变化与收束 |

每套包含配合好的材料、可选示范旋律及适用说明。它们是直接套用的创作配方。

**预听和应用使用同一份候选。**整套应用一次完成，失败保持原稿，一次撤销全部撤回。新增模板通过配置进入目录，不能每加一套内容就再写一段界面分支。

## 验收标准

八套配方逐套完成预听、应用、修改、撤销、保存和重开。缺资源、ID冲突、位置不足，都在应用前说明。

每套必须实际渲染并试听。声音合法性、削波检查和主观听感分别记录；未审听的内容不能标成已精选。

**保存点：`plan-r5-recipes`。**

# 八、R6：旋律生成、保留项和修改提示

## 实现目的

铺完和弦后，快速得到旋律，并能精确决定变化范围。

## 施工内容

### 1. 从四个动作开始

**生成一句、保留节奏换音高、保留关键音改连接、只改结尾。**

第一轮支持四和八小节的单声部旋律。输入包含和声、目标位置、节奏骨架、音域、保留项和随机种子。

生成采用分层方式：先安排节奏与乐句，再选择落点、连接落点、保留动机、调整结尾。最终检查音符整个持续时间经过的和弦。

### 2. 最多给三版有实际区别的候选

候选可以在音高、节奏或连接方式上不同。约束太严格时，允许只返回一两版，并解释原因。

全部内容被保留时，明确提示“没有可变化内容”。

### 3. “生成时保留”按维度生效

| 保留方式 | 程序必须保持什么 |
|---|---|
| 保留音高 | 指定音符的音高 |
| 保留节奏 | 起音位置和持续时间 |
| 全部保留 | 音高、位置、时长、力度及对应音符 |
| 保留一段范围 | 其中的音符、音数和休止，不能往空隙偷偷加音 |

这些约束作用于自动生成。用户主动手改时照常编辑，再更新相应保留值。

### 4. 修改提示与保留标记分开

“结构支点”“有条件变化”“装饰空间”属于建议，附具体理由。用户确认的保留项才是算法硬约束。

例如：

> “这是这句的收尾音。”  
> “这个音连接到下一小节的落点。”  
> “这里可以尝试重复、休止或另一条连接。”

### 5. 保存可复现来源

保存生成器版本、模板版本、随机种子、输入依据和最终音符。旧作品播放已保存的音符，算法升级不改变旧作品。

候选期间修改了原稿、换了作品或删掉目标，迟到的结果必须作废，不能写入错误位置。

## 验收标准

保留字段逐项不变；范围外内容不变；候选有实质差异；取消不改原稿和历史；应用一次撤销；解释有当前上下文依据。

生成速度记录设备和浏览器实测。计划给出了性能目标，不能在执行前写成已达到的表现。

**保存点：`plan-r6-melody`。**

# 九、R7：让鼓、贝斯和伴奏一起工作

## 实现目的

把局部生成扩展到多轨，同时保持每条轨道的职责清楚。

鼓点先从已验收模板做变化，支持只改镲片、只改最后一拍、变稀疏或密集。配方偏好与用户保留项分别处理。

贝斯至少参考和声，可以额外选择底鼓，提供“对齐底鼓”“呼应底鼓”两种策略。没有鼓轨时，仍能按和声生成贝斯。

伴奏参考主旋律的密集和空白位置，提供承托、呼应或同拍加强。

**每次任务采用明确的单向依赖。**例如先根据和声与底鼓生成贝斯，再根据和声与旋律生成伴奏。来源变化只标记相关结果需要复核，不自动循环重写所有轨道。

## 验收标准

只修改选定鼓件或范围时，其他内容不变；鼓件角色映射正确；多轨候选要么整套成功，要么原稿不变；保存重开后，来源、保留项和声音关系完整。

**保存点：`plan-r7-ensemble`。**

# 十、R8：从小段发展到完整编排

## 实现目的

把已有材料组织为八至十六小节，并完善混音与导出。

先做A′、回答句和结尾，再做整段编排配方。编排配方主要决定片段的位置、重复、进入退出和少量独立变化。

普通重复可以使用共享引用；A′和新句子默认独立。需要某一段换声音时，使用明确的新音轨，避免本轮再引入一套片段级音源体系。

混音继续随时可用。可以增加“应用配方建议混音”，先预听，再一次应用，明确影响哪些轨道。

## 验收标准

同一组材料能形成八或十六小节，片段不重叠、不越界；修改A不会误改A′；建议混音可撤销；长作品和超限导出给出明确结果，不静默截断。

再用一个固定工程连续编辑、试听、撤销、切换和保存三十分钟，检查异常与资源增长。

**保存点：`plan-r8-arrangement`。**

# 十一、R9：最终独立验收与交付

这一批需要从干净目录检出待发布提交，依照文档重新构建和测试，确认没有依赖未提交文件。

最终完整路径固定为：

> **新建A → 套用模板 → 修改和弦 → 生成旋律 → 保留喜欢的部分 → 局部重写 → 生成鼓／贝斯变化 → 创建A′ → 编排 → 混音 → 保存A → 新建B → 重开A → 导出 → 在新实例中重开工程。**

# 十二、每批怎样判断“完成”

完整计划中的87个验收项，都包含唯一编号、前置条件、动作和期望结果。统一使用以下状态：

| 状态 | 含义 |
|---|---|
| **PASS** | 已在记录的版本和环境执行，满足标准 |
| **FAIL** | 已执行，但结果不满足标准 |
| **BLOCKED** | 环境或依赖阻断，尚未得到结论 |
| **NOT_RUN** | 还没有执行 |
| **NOT_APPLICABLE** | 本版确实不适用，并附理由 |

每个保存点至少包含代码提交、变更说明、验收结果、原始日志、相关输入输出工程和关键截图；涉及声音时加入实际渲染音频。

**前一批的测试要继续保留。**后面做旋律生成，仍然要检查复制、撤销、保存、局部试听与导出，不能只测试新按钮。

这份计划的最终标准是：**模板能够快速铺底，算法能够尊重已有内容，用户随时可以自由修改，作品能够可靠保存并继续编辑。**教学场景留给你将来使用这个工作台时自行组织。
