# 乐构持续开发合同

先读 `README.md`、`DESIGN_SYSTEM.md`、`docs/completion-2.2.1/REPORT.md` 与 `requirements.json`。历史文档按版本理解。

1. P0是音乐操作正确、及时、可恢复。使用即时坐标；编辑与音频不等动画，取消不写原稿。
2. 一个编排工作台＋下方音乐编辑器，另有混音。音乐模板使用宽库，待用/收藏/最近/正在用在库内；不恢复常驻小托盘。音色绑定音轨，参数页不嵌套声音目录。不得恢复上下倒置的独立乐句导航。
3. 视觉源只有tokens与组件。页面负责布局；控件变体明确声明。不要在页面CSS中私改普通按钮字体、高度、颜色，不加全局覆盖皮肤。
4. 音乐磁贴有浅厚度，背景和画板安静。无背景图片、扫描光、弹簧、惯性、旋转、飞入、拍点缩放。减少动态必须仍然可用。
5. 旧作品的音色、轨道颜色、音符和资源身份保持。颜色在渲染层推导，不改文档。设计修改不提升schema。
6. 复用编辑目标、命令、PlacementPlan、CandidateSession和播放控制器。方案固定目标；输入失效及时显示；试听不提交；采用一次历史。
7. 切工具不抢音乐选择；搜索和IME优先；Mac键位与菜单来自同一配置。主保存与下载备份分开。
8. 声音预设先行，深入参数在低显著度入口。授权、GMD来源和资源摘要不可删；不能声称AMY完整运行时已接入。
9. 新增组件或例外，同时更新生产样例、覆盖表及测试。新功能要跑旧的复制、撤销、播放、导出和旧作品路径。
10. `npm run verify:engineering`执行完整工程套件，包括当前计划的600秒实际浏览器循环（旧2.1的30分钟记录是历史证据）；`verify:release`额外检查外部门槛。禁止为得到PASS删门槛或把旧构建、模拟器、脚本换名为真机/真人/子代理。
11. 打包必须从交付ZIP独立解压、测试、重建并核对HTML摘要。远端推送需要用户授权；本交付不自动推送。

12. 本轮时间编辑保持精确1—16小节残段，不把7小节分成4+2+1。旧工程可导入，含新增长度的文件需要2.2.1以上，必须如实说明兼容边界。
13. 批量位置计划和最终提交共用同一个候选。点击/原生拖动均先固定位置再确认；目标可以逐项指定。无关编辑通过补丁保留，相关修改要求重新检查。
14. 集合迁移只有一次：删除的收藏和待用项不能被旧键重新带回。找不到的素材ID保留并提示，禁止根据名字猜测使用来源。
15. 核心音乐、音色定义和真实事件是基线。修复须检验编译事件，不能只以JSON合法和按钮存在作为需求完成。
