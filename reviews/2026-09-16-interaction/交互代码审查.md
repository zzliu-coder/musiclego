# GridTone v1.3.0：交互代码审查与改进建议

日期：2026-09-16。对象：用户提供的 `GridTone_v1.3.0.zip`。本轮只读审查产品代码，没有修改软件、用户作品或发行包。

## 结论

现有工程值得继续迭代：作品数据、编辑会话、试听状态已有分离，音频使用音频时钟提前调度，参数也有平滑处理。主要短板是手势边界有漏洞、常用操作打断播放、渲染更新粒度过大，以及缺少连续编辑的空间。

建议顺序：**先修误操作和撤销问题 → 打通边听边改 → 优化高频渲染 → 落实选定的浅灰、淡紫、杏橙与局部毛玻璃风格。** 不需要为了美化先重写整个应用或更换框架。

- **PASS：现有 105 项 Node 核心测试全部通过。** 直接执行 `node --test tests/*.test.mjs`；首次因审查副本缺少示例夹具出现一项读取失败，补齐压缩包原始示例后重跑，全通过。[测试输出](evidence/core-review.tap)
- **已复现：5 个交互行为问题，以及同一吸附格内重复重绘。** 运行未经修改的 `model.js`、`session.js`、`editor-gestures.js`，在 Node VM 中替代 DOM、计时器、事件和外围回调。[结果](evidence/interaction-probes.json) · [复现脚本](evidence/interaction-probes.cjs)
- **NOT_PROVEN：真实浏览器帧率、触控板/触屏手感、实际听感、输出延迟、长时间播放及浏览器刷新恢复。** 本轮没有运行浏览器或采集音频，不能把代码风险说成已发生的卡顿或爆音。
- 源码及行号均来自原 ZIP；[原包与证据文件 SHA-256](evidence/source-manifest.json)。证据目录保留关键源码的只读快照。

## 一、先修会伤害操作信任的问题

| 问题 | 本轮证据 | 用户感受与建议 |
|---|---|---|
| 右键菜单报错 | `editor-gestures.js:354–365` 的事件处理器直接使用未定义的 `target`；复现报 `target is not defined` | 右键音符无法可靠进入操作菜单。使用当前事件目标，并覆盖网格内外、空白和音符上的右键。 |
| 点节拍刻度会加音符 | `gridPoint` 把顶部区域映射到第 0 行；`pointerdown` 未排除 `y < geo.top`。在 x=100/y=18 点击刻度，新增一枚音符。 | 用户想定位时间，却改了作品。把时间尺、琴键、音符区、力度区的命中范围严格分开；时间尺单击只移动播放起点。 |
| Esc 不取消正在进行的拖动 | `editor-gestures.js:334–336` 只清选择并 render，`drag` 仍保留；松手仍提交音符。 | 应恢复手势开始前的数据，清理计时器/捕获/预览，结束后不新增撤销项。 |
| Shift 框选丢掉旧选择 | 按下时保留选择，但 `:176–178` 每次移动都用框内集合覆盖它。 | 在手势开始时保存原选区，移动时与新框选集合合并；普通框选才替换。 |
| 小幅移动后长按可能改音高却没有撤销记录 | 从 y=53 移到 y=55：未达到 4px 门槛，却已从 72 改到 71；600ms 长按将 `drag=null`，松手不再提交。 | 实际修改必须等移动门槛通过。打开菜单前取消或规范结束当前事务；鼠标右键与触屏长按应分别处理。 |

相关证据：[手势代码](evidence/source/src/ui/editor-gestures.js)。以上是事件逻辑复现，不代替浏览器中的完整输入验证。

## 二、让“边听边改”保持连续

### 现在代码的行为

- 撤销、重做都调用 `engine.stop()`，播放位置被重置：`app.js:69–87`。
- BPM 更改直接停播：`app.js:901–904`。
- 切换试听范围先停止；退出片段/小节试听也停止并回到全曲：`playback.js:50–66`。全曲播放切换工作区则已有保留，应继续保留这一点。
- Solo 改动使 scope 改变，`audio.js:427–432` 会调用 `play()` 重建音频图；旧图会被销毁，新播放安排在准备完成后再延后 65ms。可确认存在停旧图/开新图的路径；实际空隙和尾音损失的听感尚未测量。

### 建议的统一规则

1. 全曲播放时，选轨、打开编辑器、换面板、撤销、改音量，都保持播放时钟连续。
2. Solo/Mute 通过已有轨道增益平滑切换。注意当前 `compileSong()` 只编译可听轨道：必须同时维护重新启用轨道的调度，不能只改音量而忽略未排入的音符。
3. BPM 修改维持当前位置对应的音乐拍点，重新排后续事件；不能仅删掉 `engine.stop()`，否则当前依赖 BPM 的时钟计算会跳位。延迟效果等拍速相关参数也要同步。
4. 模板/音色候选试听维持独立状态；退出后恢复先前的全曲/局部范围、位置与是否正在播放。现在关闭试听会停止候选，但没有完整的“返回之前正在听的位置”栈。
5. 普通音符编辑对未来事件生效；已排程和正在发声的音符采用明确的取消/收尾策略，避免重复触发和突然切断。

相关证据：[播放控制](evidence/source/src/playback.js) · [音频引擎](evidence/source/src/audio.js) · [应用入口](evidence/source/src/app.js)。

## 三、把高频更新拆小，才能跟手

### 1. 拖动只更新变化的音符

现在每次 `pointermove` 都调用 `drawGrid()`，最终给 `#grid-inner.innerHTML` 赋整张 SVG。网格、琴键、全部可见音符、力度条和播放指针都会重建。同一格内连续 120 次指针移动，复现得到 120 次重绘请求，即使音符数据没有进一步变化。

建议保留稳定的网格层、音符层、选择层与播放指针层；只更新变化音符和框选轮廓。事件只记录最新指针位置，每个动画帧最多更新一次；吸附后的值没变就跳过。移动多选音符时，用 ID 索引代替每枚音符再遍历所选集合。

### 2. 音量和声像不要反复编译整首歌

`app.js:943–952` 每次滑块输入调用 `playback.updateProject()`；播放时进入 `audio.js:438` 的 `compileSong(project, scope)`，然后才更新增益。重算乐谱对音量/声像等纯混音参数没有必要。

建议区分混音参数变化、音符/编排变化和资源/轨道结构变化：前者直接更新对应音频参数，后两者才按需要重编译或建图。现有 `setTargetAtTime` 的平滑处理保留。

### 3. 页面结构保持稳定

`app.js:132–164` 的 render 会替换整个 `#app`。虽然已有焦点和滚动恢复，但选轨、切面板、完成编辑等操作仍重建大块界面。应保留外壳与编辑器实例，局部更新状态，并避免一次动作在多个调用层重复 render。

### 4. 播放指针单独跑动画

`app.js:1010` 用 34ms 门槛限制全部播放视觉刷新；在固定 60Hz 的帧回调下，可能要跨三个帧间隔才更新一次。确切频率需实测，但它肯定没有逐帧更新指针。电平读数与文本可以低频更新，指针应该单独逐帧更新，仅改 transform。

相关证据：[网格绘制](evidence/source/src/views/piano-roll.js) · [事件处理](evidence/source/src/ui/editor-gestures.js) · [应用更新](evidence/source/src/app.js)。

## 四、让编曲空间符合直觉

### 编排始终在上，片段编辑器在下

选中的方向图已经具备这种结构，但现有代码的 `arrange` 和 `edit` 是整块工作区替换（`views/shell.js`），需要明确列为功能改动。

建议单击选中片段，并在下方显示其名称、轨道、起点和音符；双击放大编辑器。下方高度可拖动，也可收起。切换片段时保留各自视口。避免每次进入音符页就失去整首歌的上下文。

### 从每小节翻页，走向连续时间轴

目前只绘制 `S.page` 指定的一小节、16 个格子（`views/piano-roll.js:12–18`），通过页按钮切小节。音符数据支持跨小节，但拖动缺少边缘自动滚动，切页还会清掉选择（`app.js:534–538`）。这会妨碍连续写长句、拖长音和跨小节整理。

建议桌面端支持连续多小节画布，边缘拖动自动滚动；小屏保留单小节模式。缩放以指针或播放位置为锚点，水平时间缩放和垂直音高缩放分开。目前一个缩放按钮同时改变行高和横向倍数。

### 时间定位与循环范围

当前时间尺没有点击定位或拖动循环范围的事件绑定；模型中的 loop 主要是全曲/所选范围的开关。方向图中的循环选区不能当作已存在功能。

建议：点刻度设置起点，拖刻度划定循环段；停止第一次回播放起点，再次停止回曲首。选中状态与播放起点独立，避免选音符顺带改变下一次播放位置。

### 片段操作统一

目前编排拖动只读取 X 坐标，限同轨、整小节移动；没有跨轨拖放、片段多选拖动或 Alt 拖复制路径。可按顺序补：同轨多选移动 → Alt 拖独立复制 → 同类型跨轨移动。跨轨时明确使用目标轨音色，鼓轨与旋律轨不静默转换。

“重复引用”已有共享关系，默认批量复制与共享引用需要一眼分清：普通复制可独立修改，共享引用使用链接标记及“修改同步到 N 处”的说明，保留现有独立副本能力。

## 五、Lo-Fi / 电音需要更细的时间与力度控制

- 当前普通绘制、拖动、缩放时长固定使用 `STEP=240`（1/16）；界面的 `1/16` 是展示文字，不是可选网格。底层则是 960 PPQ，已有容纳更细时间的能力。
- 建议增加 1/8、1/16、1/32、三连音与关闭吸附；先保持拍号 4/4 即可，不必一开始扩展全部拍号。
- Lo-Fi 不应只能靠全局 Swing/随机错拍获得律动。支持选中音符的微时移、精细力度、修改前后对比试听。
- 当前力度栏按一个 1/16 格聚合，同起点的多个音符会一起改力度（`editor-gestures.js:180–184`；`piano-roll.js:47–49`）。和弦需要突出最高音时不够直接。建议有选中音符时只改所选，无选择时再编辑该格整体力度，并明确提示。
- 快捷键以当前操作区域为边界，提供可发现的工具提示。编排页目前缺少片段复制/粘贴/删除/方向键微移；音符页已有部分对应能力。Space 在按钮和表单聚焦时遵从原生控件，规则可以保留，但退出控件后应有明确的画布焦点恢复，避免用户觉得快捷键时灵时不灵。

## 六、已有基础应保留

- 浏览、缩放和选择不写入音乐撤销历史；作品、编辑会话与试听上下文分开。
- 大部分拖动在松手时只提交一次历史；`pointercancel` 和窗口失焦已有回滚路径，需要把 Esc 和长按接入同一套事务。
- 试听与应用分开；模板/和弦应用可作为一次操作撤销；音色影响整轨已有文字说明。
- 使用音频时钟、25ms 调度检查及约 130ms 提前排程，独立于视觉动画；音量/声像等参数已有平滑过渡。
- 自动保存等待 IndexedDB 事务完成再报告成功；失败状态可见。模态框已有焦点限制与返回焦点。

这些基础比换一套前端框架更值得保留。后续建议增加少量恢复版本：目前工程自动保存到单一 `autosave` 键；不能把自动保存当成完整项目库或版本历史。

## 建议实施顺序与验收

| 阶段 | 交付范围 | 验收方式 |
|---|---|---|
| 1. 操作可靠 | 右键、命中区、Esc、Shift 框选、移动门槛/长按事务 | 在真实浏览器复验本报告 5 个问题；取消零数据变化、一次有效手势一次撤销。 |
| 2. 播放连续与性能 | 播放时撤销/Solo/BPM策略、混音更新分流、局部绘制、独立指针动画 | 在目标 Mac 上边播放边拖动/调参；记录帧时间、长任务、lateWindows/skippedEvents，并录音检查切换尾音。性能指标是待建立的基线，不是本轮已达成结果。 |
| 3. 创作工作流与外观 | 上编排下编辑、连续小节、循环范围、可选吸附、精细力度、选定材质 | 完成一条真实路径：找模板 → 试听 → 改四小节旋律 → 调音色 → Solo 比较 → 撤销 → 恢复全曲 → 导出并重新打开工程。 |

毛玻璃放在固定控制条和短暂浮层；网格和大量音符使用稳定清晰的内容层。拖拽反馈立即跟手，吸附预览明确，装饰动画不得让音符追着指针走。减少透明度/动态的现有偏好继续有效。
